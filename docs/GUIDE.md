# NURBS Proto: Tool Guide

Every tool in detail, by area. For the short overview, see the [README](../README.md).

Viewport tools that build exact NURBS surfaces with NVIDIA's open-source
[USD BRep](https://github.com/NVIDIA-Omniverse/usd-brep) kernel (SMLib, Apache-2.0).
Each result is a mesh object (its tessellation) that carries the exact B-rep.

## Where things are

The sidebar tab **NURBS Proto** has one collapsible panel per group. Ctrl+click a panel header to open only that one; Blender remembers which are open, per file.

Tools that don't fit the selection are dimmed: select a curve and the tools that work only on surfaces (Offset, Thicken, Unroll, the Surface Edit tools) dim, select a NURBS surface and the tools that work only on curves dim. A tool that takes surface edges as well as curves (Loft, Loft Rails, Network, Revolve, Sweep, Pipe, Extrude, Flange, Planar, Dome, Boundary, Patch, Blend Curve, Offset on Surface) stays lit for both, and so do Trim and Split, which cut with curves, select a scan mesh and only the drawing tools, primitives, Mesh to BREP, Cage from Scan and Drape Patch to Scan stay lit. The drawing tools and primitives never dim. Dimmed tools still run. Started with nothing that fits selected, a tool asks you to pick its inputs, as Alt+click does. With nothing selected, nothing is dimmed.

Surfaces, edges and Face / Edge highlights then flicker against each other (blotchy fills, dashed edges). When the steps exceed 0.05 % of the view distance, the Display panel says so and a red ⚠ appears in the header: one click sets Clip Start to about a thousandth of the view distance. |
| **History** (closed at first) | Construction History, Live Update, Pause Rebuild, Delete History, Collect Inputs, Rebuild / Re-tessellate |

The same seven tool groups are in the viewport header's **NURBS Proto** menu (Object Mode), so every tool is reachable without the sidebar and **F3** finds each one by name. **Add** (Shift+A) has **NURBS Curves** and **NURBS Surfaces**, the two Create groups. STEP import and export are under File > Import / Export. One table in `toolgroups.py` drives the panels and the menus, so they always list the same tools.

### Key hints (every interactive tool)

While a tool runs (the sketch tools, any tool that asks you to pick, Trim, Trim Curves, Continuity Check), its hints are split three ways so they fit a laptop screen:

* **Header:** one short line with what's going on now: the step, live values (length, angle, sizes; the field you're typing in is in [brackets]) and the modes that are on.
* **Key panel**, at the bottom centre of the 3D view (of the part the toolbar and the sidebar leave free): every key, in groups (Place, Direction, Start, Reference...). A key that switches between options shows all of them with the current one in orange (*S free · **tangent** · perpendicular*), a toggle shows on or off, and an active lock lights up. The rows wrap to the free width. When the Adjust Last Operation panel is showing, the key panel moves beside it, or above it when there is no room. **?** or **F1** collapses the panel to one line and back; the choice is kept in the add-on's preferences. The preferences also hold **Value Input**: *Handles* (a tool that has them shows its result with handles to drag, see Extrude) or *Dialog* (it asks for the values in a dialog first, as before).
* **Status bar:** the mouse basics with Blender's key icons.

### Selecting faces and edges (Body / Face / Edge)

In the tool settings bar, right after Blender's selection modes:

* **Body** is Blender's own object selection.
* **Face** / **Edge**: a click picks a face or edge of a NURBS body (and selects the body), Shift+click adds or removes one. A click that misses every NURBS face and edge clears the picks and goes to Blender as usual: it selects a mesh body (or a curve) there, or deselects on empty space. What's under the mouse lights up, and this works with any tool active. Picks are kept with the object, survive rebuilds and undo, and count while the body is selected.
* **Face and Edge together:** Shift+click the second button. An edge within 10 px of the mouse is picked, otherwise the face under it. Body always stands alone: clicking it switches the others off, and adding Face or Edge switches Body off. Turning a mode off drops only that kind's picks.
* **Tools take the picks.** Edge Fillet, Continuity Check and Dome use the picked edges, and so do Loft, Planar (one edge brings its whole planar loop), Square, Boundary, Patch, Loft Rails, Duplicate Edge, Extend Surface, Pipe and Revolve, when the picks fit the tool. The tool then runs at once; otherwise it lets you pick as usual. **Alt+click** a tool to pick by hand anyway. CVs / Hulls shows only the picked faces' nets. **Unjoin** splits the picked faces off (one object each, the rest stays joined), and **X / Delete** removes the picked faces (a body whose faces are all picked is deleted; the body opens). **Shift+X / Shift+Delete** removes them and heals the gap instead (**Remove Faces**). With only edges picked, **X / Delete** is **Remove Edges**: the picked edges go where their faces merge into one.
* Clicks on the navigation gizmo (axis ball, zoom / pan / camera / perspective buttons) and on continuity labels go to them, not to picking. The gizmo also works while any tool runs (drawing, picking inputs, trimming), so you can turn the view mid-curve.

## Construction History

Every object can have a **base feature** (Loft, Extrude, Revolve, Offset, Planar, Blend Curve, a primitive, **Join**, **Surface Fillet**, **Unroll Surface**, **Flow Along Surface**) plus a **history stack** of in-place steps replayed on top of it:

| Step | Recorded inputs | Rebuilds when |
|---|---|---|
| **Trim** (Keep / Discard / Split action) | cutting curves / surfaces, the kept *side* of the cutters | a cutter or the base moves / changes |
| **Edge Fillet** | the filleted edges (matched to the nearest shared edge on rebuild), shape, radius, continuity | the joined body changes |
| **Push / Pull** | a point on each moved face and its normal (a flat face matched to the nearest flat face facing the same way on rebuild, a curved one to the face at its point), the distance | the body changes (the extrude under it taller: its top still moves) |
| **Rotate Face** | a point on each turned face and its normal (found again as Push / Pull's faces), the hinge (local), whether it was the face's own edge, the angle | the body changes (the extrude under it taller: the hinge follows the face's edge) |
| **Move Face** | a point on each picked face (the feature found again from them); on a flat face the two directions (local) and the X / Y distances, on a curved one its axis (local), Along and Turn (a sphere: its centre, the tilt axis and Tilt; a free-form face: the anchor, the two directions, X / Y and Keep Square) | the body changes (a longer plate: the hole moves the same distance) |
| **Replace Face** | the replacing surface, a point on each replaced face and its normal (found again as Push / Pull's faces) | the surface moves or changes, or the body changes |
| **Shell** | a point on each removed face, the thickness and side | the body changes (the extrude under it taller: its top still opens) |
| **Remove Fillets** | all (with Max Radius), or a point on each picked fillet; Keep Others | the body changes (all: every fillet the rebuilt body has goes; Max Radius below every fillet: the body as it is) |
| **Remove Faces** | a point on each removed face | the body changes (a face that can't be healed any more fails the step) |
| **Remove Edges** | all redundant edges, or a point on each picked edge; Flat Tolerance, Fit Tolerance | the body changes (all: every edge the rebuilt body does not need goes; a picked edge that is needed now stays, and the body is kept as it is when none can go) |
| **Fillet trim** (from Surface Fillet's Trim Surfaces) | the partner surface; the fillet is recomputed from both **base** surfaces | either surface changes |
| **CV Tweak** (Done after moving CVs with Edit CVs / Nudge CVs) | each moved CV's offset in its own frame (along its U hull line, across it, along its normal); the neighbour surfaces whose guides the moved CVs ended on | the surface before it or such a neighbour changes |

* **Join** with history makes a new joined object and keeps its sources hidden; editing a source (or its own history) re-joins, and an Edge Fillet on the joined body is replayed. **Restore Inputs** (in its Feature box) undoes the Join: it deletes the joined object and shows the sources again. It asks first when steps such as an Edge Fillet would be lost. **Unjoin** instead splits the *current* shape into one object per face (fillet faces included) and freezes it.
* **Removing a feature** (the trash icon in its Feature box) is one step back: the feature's object goes, and the objects it was built from come back, shown and selected. Remove a Thicken and its joined body returns; remove that Join and its surfaces return. Inputs another feature still uses stay hidden. **Shift+click** the trash to delete the hidden inputs nothing else uses as well. When other features are built from the one you remove, a dialog asks whether to bake them (they keep their shape) or delete them too.
* The **Feature** box shows the base feature's settings, then the steps in order. Click a step to open its settings and edit them live: Trim *Keep / Discard* (flips the kept side), *Scope*, *Projection*; Edge Fillet *Shape, Radius, Variable / End Radius, G1–G3, Fullness, Class-A Patches (Tolerance, Angle Tolerance, Max Degree, G1 / G2 ends)*; Rebuild *degrees, spans*. The checkbox **mutes** a step (it is skipped but kept) and the **X** removes it. **Untrim** removes the trim steps; **Delete History** freezes the object.
* The **Construction Tree** below shows what the active object is built from, hidden inputs included, as a tree. Each line shows the object name, its role (input / trim cutter / fillet partner) and its own history (e.g. *Cylinder → Trim*). Click a name to make that object active and edit its feature; Shift+click also unhides it. The eye shows or hides it. **Used by** lists the objects that rebuild when this one changes. An object that appears twice (two surfaces trimming each other) is expanded only once.
* Trims remember *which side of the cutters* was kept (not just the click point), so moving a cutter moves the hole instead of flipping the result.
* **Set Origin** and **Apply** (Ctrl+A: Location / Rotation / Scale) work on NURBS objects: the surface stays where it is, only its pivot (or its transform) changes. The exact B-rep follows the mesh Blender moved, and a feature remembers the change, so its rebuilds and everything built from it (a G2 blend loft to its edge) stay in place. Applying a mirror (Ctrl+M, a negative scale) keeps the side the surface showed: the B-rep is turned over with the mesh, and features built from its edges keep their edges. A shear (non-uniform scale on a turned object) can't be applied exactly and leaves the B-rep as it was (the console says so).
* **Move Pivot** (Object > Transform, or the Transform menu in Edit Mode; NURBS Proto menu; F3) moves the pivot, the object's origin, without moving the geometry, like Move Pivot in Alias and Maya. It works in Object Mode and in Edit Mode, without leaving it. **Click** where the pivot goes, or **press and drag** it there. It snaps like the drawing tools: curve and edge ends, middles, face centres, CVs, mesh vertices and edges (**Ctrl** the grid, **Alt** no snapping, **O** onto the face). The CVs of the surfaces whose pivot moves always snap: the tool draws their CV net when CVs / Hulls is off, and with a CV cage open (Tab) the cage's CVs snap. A free point lies on the drawing plane through the pivot (the view's grid plane, or the active work plane). **X / Y / Z** keep it on that axis through the pivot, the work plane's when one is active (**Shift+X / Y / Z**: in the plane of the other two). **C** puts it on the 3D cursor, **W** on the world origin, **B** in the middle of the object's bounds, and in Edit Mode **S** in the middle of the selected vertices or points. **Backspace** takes the last placement back. Nothing changes until **Enter** (Space, right-click); **Esc** leaves everything as it was. With several objects selected, every origin goes to the pivot; **T** keeps their offsets instead. Children stay where they are. NURBS objects keep their exact B-rep in place and their features remember the change, as with Set Origin. On a CV cage (Tab on a surface), the surface's pivot moves and the cage stays open. One **Ctrl+Z** takes the move back, in Edit Mode too. Meshes and curves whose data other objects share are skipped (as Set Origin does). No key is assigned: right-click the menu entry > Assign Shortcut (Maya uses D or Insert).
* **Align Parts** (hold **A** in Object Mode, a tap still selects all; the toolbar, after Move Pivot; Object > Transform; the right-click menu; NURBS Proto menu; F3) mates one part with another. **Click an element of the part to move**, then **one of the part it goes to**. Elements: a **Ring** (a circular edge or curve, or a round mesh edge loop: its centre and axis; hover the rim or the centre), an **Axis** (the side of a cylinder, cone or other turned face; a mesh cylinder too), a **Face** (a flat face; at its centre a pinned **Center**), an **Edge** (a straight edge: its line), a **Point** (vertex, end, CV; an edge's **Mid** also carries the edge's direction) and a **Sphere** (its centre). The part turns the least that lines the two up (faces flush and facing each other, a peg's end ring onto a hole's rim, axes coaxial, edges parallel, an edge into a face; two flat faces also line up their edges) and moves the least that brings them together: a pinned element (point, ring, centre) lands exactly, an edge or axis may slide along itself, a face within its plane. It turns about the point you picked, so a part far away isn't thrown round the origin. Hovering the target shows the result as a ghost. After the second click: **F** flips (faces back to back, the other way along an axis), **R** spins a quarter turn about the mated direction, **Shift+R** 15°, a **typed number** is a gap off the target (negative: into it; **Tab** fixes it), **D** leaves the original and puts a copy there. A click on the moving part starts a **second pair** (its element, then one of the target) that sets only the spin: pick two side edges or faces and they line up, the first mate kept. A click on another part makes that element the new target. **Enter**, Space, right-click or a click on nothing applies it; **Backspace** steps back, **Esc** cancels. What moves: the selection when the first element lies on it, else just that object (no need to select first). It is one undo step, and the Adjust Last Operation panel changes Flip, Spin, Gap and Copy afterwards. From the toolbar the first click is the first element, and the tool before it comes back when it ends. Object Mode only; a NURBS copy is a fresh object with the same B-rep (no history).
* Steps run in the worker process. Split and Unjoin are one-shot. With **Construction History** off, every tool behaves as before (one-shot).

### Feature panel ("query edit")

Every object with construction history shows a **Feature** box in the **Active Object** panel at the top of the sidebar: Loft, Blend Curve, Extrude, Revolve, Offset, Planar and all primitives. It holds that feature's settings (G0/G1/G2, G3 for a Loft's sides and a Blend Curve's ends, weights, curvature, radius, degree, spans…) as live controls. Changing one rebuilds the object at once, and everything built from it updates through history. A blend curve or loft therefore stays editable for as long as it keeps its history, instead of being a one-shot result.

**Pause Rebuild** (top of the Feature box, and in the History panel) holds every rebuild back: settings, continuity labels in the viewport, Patch corners and guides change at once without a solve, and input edits wait too. The labels of a waiting object get a grey-blue ring (not checked yet), its info line says *waiting for Rebuild*, and the viewport says *Rebuild paused · N waiting*. **Rebuild** (red while anything waits) builds them, upstream first, and what is built from them; switching the pause off does the same.

## Create Curves

**Shapes** (Line, Arc, Circle, Ellipse, Rectangle, Polygon, Helix) are placed at the 3D cursor and stay editable: see [Primitives and shapes](#primitives-and-shapes).

| Tool | Inputs | Notes |
|---|---|---|
| **Blend Curve** | 2 curves, sketches or surface edges: click each near the end to blend from, or select two curves (nearest ends). **P** blends from the point you click along it instead (a closed sketch, such as a circle or a rectangle, always does). A click inside a surface's face blends from that point of the surface | A Blender NURBS curve, a single Bezier span (degree 1 + the two sides' levels: 1 / 3 / 5 up to G2-G2, 7 for G3-G3). Per side: **G0 / G1 / G2 / G3**, **Weight** (tangent length = weight × distance between the ends), **Curvature** (G2 / G3 shape) and **Flip**. Matches tangents and curvature exactly; **G3** also carries on the curve's third derivative (from its CVs, rational too), so the curvature's rate along the curve and the torsion match as well. **Surface** (a side on a surface edge or face): *Tangent to Surface* (edges, the default) leaves the surface square to the edge and in its tangent plane, G2 / G3 carrying on its normal curvature and that curvature's rate; *Perpendicular to Surface* (faces, the default) leaves along the surface normal and starts out straight: G2 / G3 add no curvature across it, as the normal line would; *Symmetry Plane* also leaves square to it, but joins its own mirror image smoothly (G2 curvature continuous through the mirror, G3 its rate too): **Curvature** then bends the blend at the plane (0: straight out) and **Rate** is G3's free amount; *Continue Edge* continues the edge as a curve. **Point Along** / **Position** (F9, Feature box) move a side along its curve or edge. Directions that a point alone doesn't fix (a point along a curve, the normal) lead toward the other side. Follows its inputs with construction history and works as input for every other tool. |
| **Iso Curve** | An untrimmed surface | Isoparametric curve at a U or V position: the exact isoparm, its CVs blended from the surface's CV grid (same degree, knots and weights), not a dense fit. |
| **Duplicate Edge** | Pick surface edges, Enter | The edges as Blender NURBS curves, each the edge's exact curve (degree, knots, weights), cyclic when closed: a cylinder rim is its 8-CV rational circle, a trimmed edge the trim's own curve. Only a curve above degree 5 (Blender curves stop at degree 5) is still fitted. |
| **Project Curve** | Curves + the surface (active) | Curves on the surface, projected along the active work plane's normal (World Z when the World is active), the view or a world axis. Onto a flat face the result is exact: the curve's own CVs moved onto the plane along the direction (same degree, knots, weights and CV count), cut exactly where it runs over the face's edge. Onto a curved surface it is fitted within 1e-4 of its size. A curve that misses the surface leaves Adjust Last Operation open to change the direction. |
| **Intersect** | Two surfaces | Their intersection curves. |

### CV Curve / Draw Line (sketch tools)

Both are under Create Curves. You click in the 3D view to draw.

* **CV Curve.** Each click places a CV, or with **Through Points** (key **M**) the curve passes through every click.
  * The result is always one clean uniform NURBS spline: Endpoint on and no Bezier knot stacks. Curvature stays continuous, and moving a CV later never makes a kink.
  * Keys: **1-5** set the degree (with Blender's *Emulate Numpad* on, the top-row digits arrive as number-pad keys and still set the degree; the number pad then doesn't switch views during CV Curve). **K** shows the curvature comb on the curve while you draw it, with its knot ticks (the same switch as Analyze > Curvature Comb, so it stays on for the finished curve). **C**, or clicking the first point, closes the curve as a smooth periodic loop. **H / V** lock the next CV horizontal or vertical from the previous one.
  * **Start / End conditions.** An end snapped onto a curve or sketch (its end, its middle or any point on it), onto a surface edge, or onto a surface's face (face snapping on, **O**) is **G0**, **G1**, **G2** or **G3** to it. **S** and **E** step the start's and the end's condition G0 → G1 → G2 → G3 while you draw (G1 by default), and the preview shows the result live. G3 raises the curve to degree 4.
    * **Which edge or face** (as in Shapr3D): the edge the end follows is drawn white, and with Tangent to Surface its face is outlined in beige. The label names the reference only when that tells you something: a face (*Edge · Face 1/2 (T)*), or a choice (*End · Edge 1/2 (T)*); a single edge just reads *Edge*. Where there is a choice, **T** cycles it: the two faces along an edge, or the edges meeting at a corner. T works on the point under the cursor, or on the placed start when the cursor isn't on a snap. **F** steps through tangent to the face → perpendicular to it → symmetry plane → continuing the edge. The chosen face is kept in the Align history step.
    * **Which way across the surface** (Tangent to Surface): **Square** (the default) leaves square to the edge; **Angle** at a set angle from it, turned round the surface normal (90 is square; on a face it is measured from the surface's u direction); **Along Curve** follows a curve lying on the surface through the end, such as a projected curve; **Free** follows the curve's own CVs, as before. Square, Angle and Along Curve add no sideways bend at G2 / G3, so seen down the normal the end starts out straight, and the curve meets the surface's cross-section there with G2 / G3. Along Curve takes the guide's own sideways bend (and its rate at G3) instead, and the guide becomes an input of the Align history. **R** aims an end: the hovered end when it snaps onto a surface edge or face (it is placed when you confirm), else the placed start. The mouse turns it round the normal, snapping to square, along the edge, the u / v lines and curves on the surface; **Shift** steps 15°, **Alt** turns snapping off, click / Enter / R sets it, Esc puts it back. R on an end snapped onto a curve that ends at a surface edge (a projected curve, whose end is often a hair off the edge) moves that end onto the edge and aims it along the curve. **D** switches both ends between Square and Free. The F9 panel and Align Curve have the same **Direction** / **Angle**; Blend Curve's Tangent to Surface sides have an **Angle** (90: square, as before).
    * **At a corner** where edges meet, the edge you slid along into it stays the reference. So running along a straight edge into its end keeps the straight edge, not the arc that meets it there.
    * **L locks onto the edge** (CV Curve and Draw Line): press L while an edge is highlighted, at a corner after picking it with T. The point then slides only along that edge, wherever the mouse is, and still snaps to its ends and middle. The reference is that edge alone (*End · locked (L)*). The lock holds for one point: placing it, or L again, releases it, and X / Y / Z / H / V replace it.
    * It is solved exactly as **Align Curve** solves it. On a curve's end the new curve continues that curve. Along a curve it leaves tangent to it, the way you drew it.
    * On a surface edge it stays tangent to the surface, and G2 matches the surface's normal curvature in the curve's direction (G3: also its rate, contact of order 3). **On Surfaces: Perpendicular to Surface** leaves square to the surface instead, along its normal: G2 / G3 add no curvature (nor its rate) across it, as the surface's normal line would. The end leaves on the side your other clicks are. **Symmetry Plane** (for a mirror plane) also leaves square to it, but keeps the curve's bend there: the curve and its mirror image join as one smooth curve (G2: curvature continuous through the mirror, the CVs mirror cleanly; G3: the curvature's rate too). **Continue Edge** continues the edge itself.
    * **On a face** (with **O**, face snapping, on): the end sits on the surface where you clicked and is tangent to it or perpendicular to it (F). With Continue Edge set, a face end is perpendicular.
    * In CV mode only the end CVs move (G1 the 2nd, G2 also the 3rd); the other CVs stay where you clicked. A G3 end adds one CV next to it rather than taking a 4th click, so it moves the same clicks as G2 and the curve keeps the shape you drew. Through Points adds one CV per G1 end, two per G2 end and three per G3 end (and one more per G2 / G3 end for room), so the curve still passes through every click. Of all such curves it takes the fairest (least bending): the end's tangent length, what G2 / G3 leave free and how the clicks are spaced along the curve are all chosen for it, so clicks close to an aligned end that turn away from it give a short, clean turn, not a loop. When the ends need more, the degree is raised (G1 needs 2, G2 needs 3, G3 4), and a curve with too few CVs is refitted, with the CVs its ends take added to its own.
    * **History (Keep Aligned, key A, off by default):** G1 / G2 ends are always aligned while you draw, but by default the result is a plain curve with no history. Tick **Keep Aligned** (or press **A** while drawing) and, with Construction History on, the curve also gets an **Align Curve** history step at once: its ends then stay G1 / G2 when the target changes and while you edit the CVs. You can add the same step to any curve or line later with **Align Curve**; for a curve that only bridges two ends, use **Blend Curve**. A curve that is only G0 to its targets gets no history. In curve Edit Mode, or with history off, the ends are aligned once.
  * Mode, Degree, Closed, Start, End, Keep Aligned and On Surface Edges can still be changed in the Adjust Last Operation panel afterwards; it also says which targets each end was aligned to and whether the history step was added.
* **Draw Line.** Click the start, then click the end; each line is its own 2-CV curve.
  * **Exact lines:** after the start point, type a length and press **Enter**. A plain number is in the scene's length unit, and unit letters work too (`3`, `2' 6"`, `2ft 6in`, `10mm`). Number-pad digits type too, and so do the top-row digits with Blender's **Emulate Numpad** on (which sends them as number-pad keys). Before the first click there is nothing to type into, so those keys still switch the view.
  * **Tab** switches to the angle field, in degrees counter-clockwise from horizontal (`90` = straight up, `-45`, `30+15`). A typed angle on its own locks the direction and the mouse sets the length.
  * A line placed by typing chains on: the next line starts at its end, so `3` Enter, Tab `90` Tab `2` Enter draws an L. Backspace edits the typing, then drops the pending start.
  * Horizontal and vertical need no key: the smart guides hold the line straight across or up when it is close (Aligned). **X / Y / Z** lock a world axis (below). **Shift** snaps to 15°.
  * With an axis lock (below), a typed length goes along that axis.
  * **Perpendicular / Tangent end:** once the start is placed, the end also snaps where the line meets a curve or surface edge at a right angle (**Perpendicular**), or where it touches one (**Tangent**). Move the mouse near that point (within 24 px) and it clicks in, with the label beside the snap dot. Both points are solved exactly on the curve, not on its drawn polyline. A right angle works on any curve or edge, in 3D. Tangent works on planar curves (circles, arcs, ellipses, planar splines) when the start lies in their plane; a straight line has no tangent point. Ends, middles, centres and CVs nearer the mouse still win. A lock of your own (H / V / X / Y / Z / A), Ctrl or Shift switches these snaps off.
  * **Start (S)** cycles **free → tangent → perpendicular**, for a line started on a surface edge or a curve:
    * **Tangent** leaves tangent to it (G1). By default it runs along the edge's tangent at that point: a tangent line to a rim, or straight on from an edge's end. **F** switches to tangent to the face: the line stays in that face's tangent plane. A line can only be G1: it has no curvature, so G2 to a curved edge isn't possible.
    * **Perpendicular** leaves square to it: in the curve's plane for a planar curve, in the face's tangent plane with **F**, else in the drawing plane.
    * **Sliding to a second curve:** with a tangent or perpendicular start, move the end onto another curve and the start slides along the first one to meet it. Tangent at both ends gives a **line tangent to two circles**. Of their four such lines, you get the one on the side you started and nearest the mouse. Perpendicular at both ends gives the shortest line between two curves; mixed gives tangent to one and square to the other (labels *Tangent to both*, *Perpendicular to both*, *Tangent · Perpendicular*).
    * **T** picks which edge or face, as in CV Curve, and the reference is highlighted the same way. A start on a circle's quarter point (a CV that lies on the curve) counts as on the circle. A typed length goes along the tangent or the square direction. The direction is set once, while you draw; lines get no history.
  * **Parallel / square (A / Shift+A):** with the mouse over a line, curve or edge, **A** locks the line's direction parallel to it, **Shift+A** square to it (in its plane, or the drawing plane). For a curve it is the direction at the point under the mouse. The reference stays highlighted. Press A before or after the start; the lock holds for one line, and pressing it again unlocks. A typed length goes along it.
  * The header shows the live length and angle (counter-clockwise from horizontal in the drawing plane).
  * **Polyline** (key **P**, or the Adjust Last Operation panel): every click adds a segment. The next line starts where the last one ended, so you just keep clicking. Clicking the first point again closes the polyline. Backspace steps back one segment, and Enter or right-click finishes. The lines become one degree-1 curve (closed if you closed it).
  * **Arcs (key R):** switches the next segments between lines and tangent arcs (and turns Polyline on). An arc leaves the last point in the direction the previous segment ended, and ends where you click. Or type it: the fields become **Radius** and **Angle** (Tab), the angle measured from the direction the arc leaves, so **90 makes a half circle** (the arc sweeps twice the angle; the header shows it). A radius alone keeps the end on that circle, following the mouse; the mouse picks the side. Press R again for lines. A slot: a line, R, the arc across the width, R, the line back, R, the arc back to the first point. A polyline with arcs becomes one exact curve (order 3, rational, Bezier knots), closed if you closed it. While drawing, the arcs already placed snap like the lines: ends, middles and any point on them.
* **Snapping and placement**
  * Clicks snap to what is near the cursor on screen (12 px). A small label beside the green snap dot names the target:
    * **End**: the ends of visible curves and of surface edges (B-rep vertices), and the points drawn so far.
    * **Mid**: the middle, by length, of a curve or surface edge, and of each line drawn so far (Draw Line).
    * **Center**: the centre of a circle or an arc (a curve, or a circular surface edge such as a cylinder's rim), exact; and the centre of a face, worked out once the cursor is over the face. A planar face gives its area centroid (a disk's or a hole's centre); a curved face gives the point on the face nearest its centroid; a face that wraps around its centroid (a cylinder, a sphere) gives the axis or centre point itself.
    * **CV**: the CVs of curves, and of surfaces whose CV net is shown (**CVs / Hulls** on and the surface selected, or a selected Square).
    * **Edge** / **On Curve**: any point on a surface edge or a curve, when none of the above is near. The point is put exactly on the edge (the kernel's closest point on it), or on the curve's own spans, not on the drawn polyline.
    * **On Line** (Draw Line): any point on a line drawn so far in this run, so a polyline can come back onto itself.
    * **Perpendicular** / **Tangent** (Draw Line, for the end): see above.
    * **Meshes** snap like curves and surfaces, always: **Vertex**, **Edge** (any point on an edge), **Edge Center** and
      **Face Center**, as the view shows the mesh (modifiers applied: a SubD body snaps on its smooth surface). Only what
      faces the viewer snaps. A CV Curve end on a mesh is G0 only (G1 / G2 / G3 need a curve, a surface edge or a NURBS face).
    * **O: on surface.** While drawing, **O** switches face snapping on and off: with it on, a point that isn't near
      anything else lies on the mesh face under the cursor (it leaves the drawing plane). It stays as set for the session
      and shows in the key hints.
    * **Alt: no snapping.** Hold **Alt** to place a point freely on the drawing plane, for example over a dense mesh where
      a vertex or edge is always near. A first point placed with Alt also stays on the view plane, not on the face under
      it. (With Blender's Emulate 3 Button Mouse on, Alt+click orbits the view instead.)
    * **Unselectable objects never snap**: lock a scan, a blueprint or any reference out of snapping by making it
      unselectable (the arrow in the outliner).
    * **Scan data:** a mesh is read the first time the cursor comes near it (about 1.4 s for 2 million faces) and kept
      for the session, so later tools start at once; it's read again only when its geometry changes. After that a dense
      mesh snaps as quickly as a cube. A point cloud (more than 200,000 loose points) snaps only on its faces, not point
      by point. To keep a scan out of snapping, make it unselectable.
  * **Smart guides** (dashed): the point also snaps onto lines in the drawing plane, within 6 px. Through the points drawn so far and the last points you snapped to (hover a line's end, then move away: its guides stay) they run horizontal and vertical (Aligned), and parallel and perpendicular to the sketch's lines (the 4 newest directions): the perpendicular through a slanted line's end is where an arc makes a half circle; and in Draw Line, from the last point, straight on (Extension, or Tangent after an arc), square to it (Perpendicular) and parallel to the lines drawn (Parallel). Where two guides cross, that point wins over edges, so a slot's return line ends exactly square to its start. With an X / Y / Z lock or a typed angle the point stops where the lock line crosses a guide. Ctrl, Shift and Alt switch guides off.
  * Ends win over the others, then middles and centres, then CVs. Where targets overlap on screen (a box's top and bottom centres in a top view), the one nearest the viewer wins.
  * **Ctrl** snaps to the grid lines the view shows: the finest grid level drawn at least half visible (whole inches, feet... in Imperial; mm, cm, 10 cm... in Metric), so a point never lands between visible lines. Zoom in for a finer step. In a perspective or turned orthographic view Blender's own floor grid stops at 1 m (1 ft); NURBS Proto draws the finer levels on the floor there (mm, cm, 10 cm; inches), as a Top view has them, so Ctrl has lines to land on. **Display > Fine Grid** (or its grid icon in the header) shows or hides them; Blender's Floor overlay hides them too. **Shift** snaps to 15° steps from the previous point. Both keep the point snaps (ends, middles, centres, CVs) but switch the edge snap off, so the grid and angles aren't overridden by every edge nearby.
  * **Axis locks (both tools):** **X**, **Y** or **Z** locks the next point to that world axis through the previous point (through the world origin for the first point), like G X in Blender. **Shift+X / Y / Z** excludes that axis instead: the point moves in the plane of the other two, so Shift+Z keeps the previous point's height.
    * The locked axis, or the plane's two axes, are drawn in the axis colours. Pressing the key again unlocks.
    * A lock holds for one point; for a CV Curve, press the key again for the next CV.
    * A snapped point is projected onto the lock's line or plane. **Ctrl** steps the distance from the previous point in grid increments.
    * An axis seen end-on can't be moved along with the mouse: the point stays put (type a length with Draw Line). A plane seen edge-on takes the drawing-plane point under the cursor, projected into the plane.
  * **Drawing plane.** The first point chooses the plane the sketch is drawn on:
    * **On a flat face** (a box side, a cylinder's cap, a flat NURBS face, a mesh's flat face even when it is
      triangulated or bevelled): that face's plane, its axes along the face's edges. Before the first click the face
      under the cursor is outlined, with small blue squares on its corners (where the outline turns by 20° or more) and
      the middle of each side; a free first point lands on it, and so does one snapped to its vertices, edges or
      centre. The squares snap (on a mesh, the middle of a side made of several edges too), and the outline stays while
      you draw. A rectangle then lies flat on a slanted face, square to its edges, and a circle sits on it. In Draw Line
      every new line (not one chained on) can start on another face.
    * **Elsewhere**, over a curved surface (a cylinder's side, a sphere, a scan, a SubD body: neighbouring facets about
      as large that bend by less than 30°) or with **Alt** held, on a world grid plane through the world origin (or
      through the first snapped point):
      * in a **Top, Front or Side** orthographic view, that view's grid plane;
      * in **any other view** (perspective, or orthographic turned), the world's **XY plane**: the floor grid, so
        **Ctrl** lands on its lines. Looking almost level with it (within 12°), the sketch goes on whichever of the
        world's upright planes (XZ, YZ) faces you more. The sketch never lies in the screen plane, which turned with
        every orbit and matched no grid.
      * The **3D cursor** plays no part: it places new objects (Shift+A), not sketches. For a slanted construction
        plane, place a mesh plane (or a NURBS plane) and sketch on its face: it outlines, its corners and side
        middles snap, and Ctrl's grid sits square on it, its lines through the face's centre.
  * In curve Edit Mode the new curve becomes a spline of the object being edited.
* **Other keys:** Backspace undoes the last point (or line), Enter or right-click finishes, Esc cancels.
  * Navigation (middle mouse, wheel, numpad) keeps working while you draw.

### Arc, Circle, Ellipse, Rectangle, Polygon, Slot

Drawing tools with the same snapping, smart guides and keys (Ctrl grid, Alt free, O on surface) as Line. **M** switches
the mode (shown in the key hints); type a value and press Enter, Tab for the next one. Each ends as an exact NURBS
circle or arc (rational, like Blender's own), placed where you drew it, with its radius (and angle) editable later in
the Feature panel. Circle, Arc and Ellipse can be **Smooth** instead (degree 3, not rational): **D** switches.

* **Circle**
  * **Centre:** click the centre, then the radius (or type it).
  * **2 Points:** two points across it, its diameter (type the diameter).
  * **3 Points:** through three points.
  * **Tangent:** click two straight lines or edges, then move into the corner you want: the circle touches both; its
    size follows the mouse, or type the radius.
  * **Kind** (**D** while drawing; shown in the key hints, kept for the next circle, in the redo panel too):
    **Exact** is the rational circle (degree 2): a true circle, for exact cylinders, holes and revolves.
    **Smooth** is a periodic degree-3 curve with **Spans** CVs (8 by default; not rational, within 0.1 % of the
    radius): even CVs to pull and blend, as Alias's default circle or Rhino's deformable one. The Feature panel's
    Degree changes it later either way.
* **Arc**
  * **3 Points:** start, end, then a point the arc passes through.
  * **Centre:** centre, start (the radius), then the end. The mouse sweeps either way round, past 180 degrees too;
    type the angle.
  * **Tangent:** start on a curve, line, surface edge or mesh edge; the arc leaves along it: at a curve's end it
    carries the curve on (outward, it never turns back), mid-curve the way the mouse clearly goes. Then
    click the end, or type the radius and (Tab) the angle: 90 is a half circle.
  * **Fillet:** click two straight lines or edges, then the corner: the arc between the two tangent points, with the
    radius from the mouse or typed. It doesn't touch the lines; to trim them too, use **Fillet** (below).
  * **Kind** (**D**, as for the circle): **Exact** is the rational arc. **Smooth** is a degree-3 arc with **Spans**
    spans (4 by default, in the redo panel), fitted to the arc and ending exactly on its ends, well within 0.1 % of
    the radius for a 90-degree arc.
* **Ellipse**
  * **Centre:** the centre, the end of the major axis (its length and direction), then the minor size.
  * **Axis:** both ends of the major axis, then the minor size. Type the major radius (or the axis' full length), then
    the minor radius.
  * **Kind** (**D**, as for the circle): **Exact** is the rational ellipse. **Smooth** is a periodic degree-3 curve
    with **Spans** CVs (8 by default), close to the ellipse, with even CVs to pull.
* **Rectangle**
  * **2 Corners**, **Centre** (centre, then a corner), or **3 Points**: two corners along one side (it can be at any
    angle), then the other side's length.
  * Type the width, Tab the height, Tab the **corner radius**: the corners become exact quarter circles. The corner
    radius is kept for the next rectangle, and it is in the Feature panel with the width and height.
* **Slot:** click both arc centres, then the width (type the length, then the width). One exact closed curve: two
  lines and two half circles, with its length and width in the Feature panel.
* **Polygon**
  * **To a Corner** or **To a Side:** the centre, then a corner, or the middle of a side (the side then sits square to
    the mouse). **Up / Down** change the number of sides (shown in the key hints). Type the radius.

### Helix (drawn in 3D)

* **Centre:** click the centre, then the start (its radius and where it starts round), then the height: the mouse moves
  along the axis, square to the drawing plane, up or down; snap to a point to rise level with it, Ctrl for grid steps.
  Looking straight down the axis (a top view) the mouse can't show a height: type it, or turn the view.
* **Around:** click a circle or a circular edge (a cylinder's rim): the helix takes its centre, radius and axis (facing
  you). Then click where it starts on that circle (it slides round the circle and snaps, e.g. to a seam's end), then
  the height. It sits exactly on that cylinder or cone.
* **On a cone:** snap the height to the cone's other rim (any circle on the helix's axis), to its seam line, or to
  its tip (a pointed cone): the helix takes that height and the cone's taper, so it follows the cone all the way --
  to the tip it narrows to nothing (the header says "taper ... from the cone"). A typed taper still wins. A tapered
  helix is fitted with the same CVs for every turn, so it hugs the cone even in the small turns near the tip.
* Type the **height** (negative: the other way), Tab **turns**, Tab **pitch** (sets the turns from the height), Tab the
  **taper** (degrees: narrower on top, like a thread on a cone). **L** makes it left-handed. All of it stays editable in
  the Feature panel (Left-Handed is a switch there too); the Helix shape is in Shift+A for placing at the 3D cursor.

### Fillet (Between Curves)

Rounds the corner between two curves, like Rhino's curve fillet. Click the first curve, then the second, near the
corner: the parts you click are the parts kept. The radius follows the mouse along the corner's bisector, or type it
and press Enter.

* The arc is exact (rational) and tangent to both curves; straight lines are filleted exactly, curved ones are solved
  on the curves themselves (a line and a circle, two splines).
* **T** trims both curves back to the arc's tangent points (on by default); **J** joins the trimmed curves and the arc
  into one curve. Without Join the arc is its own curve object.
* Two segments of **one polyline** (a Draw Line polyline): that corner is rounded in place, and it stays one curve.
* A closed curve (a circle) is not trimmed, only touched by the arc. A curve with construction history loses it when
  it is trimmed (as with Trim Curves). Radius, Trim and Join are in the Adjust Last Operation panel afterwards.

### Offset Curve (From Curves)

Offsets the selected curves by a **Distance** within their plane. The plane is the one the curves lie in; straight
lines and non-planar curves use the active work plane (World: XY). **Plane: Work Plane** always uses the work plane.
A positive distance goes **outward** on a closed curve and to the **left** (seen from the plane's normal) on an open
one; **Flip** goes to the other side, **Both Sides** makes both.

**Handle:** the offset is drawn as a preview before anything is made, with an arrow on the curve (where the mouse
was, when started by a shortcut in the view; else halfway along) pointing to the side a positive distance goes. Drag
it (across the curve for the other side), type a distance, click away or Enter to make it. **F** flips, **B** both
sides, **C** cycles the corners (sharp / round / chamfer), **J** joined / individual. The preview is the same offset
with its corners, trims and cut-out loops, but free-form pieces are drawn as their offset points joined by lines
instead of the fitted spline (within about 0.001 of the size); the fit runs when you make it.

* **Individual**: every selected curve object gets its own offset (corners inside one curve are still handled).
  **Joined** (default): curves whose ends touch (within 0.001) are chained first, flipped as needed, and each chain is
  offset as one curve (four separate lines of a rectangle give one offset rectangle).
* **Lines and circular arcs are offset exactly**: a line moves, an arc keeps its centre and weights and changes its
  radius. An arc that would shrink to nothing (a rounded rectangle offset inward by more than its corner radius) is
  dropped and its neighbours meet in a sharp corner.
* **Free-form spans** are fitted as uniform splines within **Tolerance** (default 0.0001), through the exact offset end
  points and with the original's end directions, so they stay G1 to the exact pieces next to them. Where the distance
  is larger than the curve's radius of curvature on that side the offset would fold into a little loop: the loop is cut
  out and the offset gets a corner there.
* **Corners**: on the inside of a turn the two offset pieces are trimmed where they cross; on the outside the gap is
  closed **Sharp** (both extended by tangent lines until they meet), **Round** (an exact arc about the original
  corner) or **Chamfer** (a straight line). A short edge between two inside corners that the offset uses up is
  dropped (a trapezoid offset far inward becomes a triangle).
* A warning says when the result still crosses itself (the distance is too large for the shape, e.g. two arms of a U
  meeting); that crossing is not trimmed.
* With construction history the offset follows its source curves, and Distance, Curves, Corners, Flip, Both Sides and
  Tolerance stay editable in the Feature panel. The sources stay visible.

### Offset on Surface (From Curves)

Offsets curves that lie on a surface by a **Distance** measured **along the surface**: every point walks square to the
curve on the surface (the straightest path there) for the distance, so a border strip, a panel gap or a split line
next to a trim keeps its width across the curvature. The result lies on the surface (within Tolerance): use it to
Trim, Split or Project.

* **Inputs**: select curves on the surface (drawn on it, projected, intersections) and start the tool; the surface is
  the selected NURBS object, else the one the curves lie on is found. With no curves selected (or **Alt**), click
  curves or **surface edges** (a trim edge, a hole's edge, a boundary) and press Enter. Curves a little off the surface
  are pulled onto it first (the report says how far). Touching inputs are chained and offset as one. A dense
  polyline (Intersect, Project Curve onto a curved surface) is made a smooth spline through its points first, within a quarter of Tolerance.
* **Side**: a positive distance goes **outward** on a closed curve, to the **left** (seen from the surface's outside)
  on an open one. **Flip** goes to the other side, **Both Sides** makes both.
* **Across faces**: on a joined body the walk goes on into the neighbouring face; where it crosses a crease (a box
  edge) the offset gets an exact corner on the edge. Where it runs off the surface (a free boundary or a trim edge) the
  offset ends there: pieces whose points would land off the surface are cut out, ending exactly on the trim. A walk may
  cross a hole on its way and land beyond it.
* **Corners** of the input: on the inside of a turn both pieces are trimmed where they cross; on the outside **Sharp**
  (both offsets continued along the surface until they meet), **Round** (a circle on the surface about the corner) or
  **Chamfer** (a line on the surface between them). Where the distance is larger than the curve's radius of curvature
  on the surface, the fold is cut out (a corner there).
* **Handle**: as in Offset Curve, the arrow stands on the curve (where the mouse was, else halfway) and walks along
  the surface as you drag; type a value, click away or Enter. **F** flips, **B** both sides, **C** cycles the corners.
  The preview walks with fewer samples and steps and draws the points joined by lines; the cubic fit (within
  Tolerance, corners kept) runs when you make it.
* Accuracy: on a sphere a latitude circle offsets onto the latitude d / R further within 2e-5 of the radius at
  Tolerance 0.0001; on a plane and a cylinder the offsets are exact up to the fit.
* With construction history the offset follows its curves and the surface; Distance, Corners, Flip, Both Sides and
  Tolerance stay editable in the Feature panel.

### Profile (circle, ellipse, square, rectangle perpendicular to a curve)

Under Create Curves, next to CV Curve and Draw Line: a section for Sweep or Pipe, standing perpendicular to a curve, a line or a surface edge.

* **On a mesh edge**: the profile stands perpendicular to the edge and square to the face the edge bounds. It's a one-off: it doesn't follow the mesh when that changes, and the redo panel has no Position slider for it.

* Move onto a curve or surface edge: a preview of the profile follows the cursor, and the snaps work as in the sketch tools (End, Mid, any point on it). Click for the centre, then drag out the size or type it (**Tab** for the second size of an ellipse or rectangle) and click or press **Enter**. Enter without typing uses the sizes in the panel.
* **C** circle, **E** ellipse, **S** square, **R** rectangle. **Ctrl** steps the size in grid increments.
* **Orientation:** the profile's plane is perpendicular to the tangent at that point. On a surface edge its "up" (local Y) follows the surface normal, so a square stands square to the surface. On a curve it follows world up (Z; Y for a vertical tangent). **Rotation °** turns it about the tangent. Where an edge is shared by two faces, or edges meet at a corner, **T** picks which edge and face, and **L** locks onto an edge, as in the sketch tools.
* The Adjust Last Operation panel has Shape, Radius / Radius 2 or Size X / Y, **Position** (0 to 1 along the curve or edge: slide it along), Rotation, and Degree (Exact = rational) and Spans for circles and ellipses.
* **History:** with Construction History on, the profile stays perpendicular at that position when the curve or edge changes, and its settings are in the Feature panel. Moving the profile object by hand is undone by the next rebuild, as with any history feature. With history off it's a plain circle or rectangle feature placed there once.

### Split / Trim Curves

* **Split Curves** cuts the selected curves where they cross each other. **Cut By Each Other** splits every selected curve; **Active Curve** splits only the others and keeps the active curve whole. Each piece becomes its own curve object.
* **Trim Curves** is interactive. The piece under the mouse is highlighted; click to delete it. The cutting curves are the selected curves, or every visible curve when nothing is selected.
  Keys: **V** toggles apparent crossings, **Backspace** undoes the last trim, **Enter** or **right-click** finishes, **Esc** cancels them all.
* **Exact.** The pieces are cut from the original Bezier spans (rational ones too), so circles and arcs stay true circles and arcs.
* **Crossings.** Two curves cross where they come within **Tolerance** (default 0.0001). **Apparent (View)** also counts curves that only cross as seen along the view, at different depths.
* **Closed and touching curves.** A closed curve cut at k points gives k pieces. A curve that only touches another at its own end point is not cut.
* **History.** Trimming or splitting a curve that has construction history removes the history.

### Rebuild / Extend Curve

* **Rebuild Curve** refits the selected curves as one clean, uniform, non-rational spline with a chosen **Degree** (1-5) and evenly spread CVs. It works well after Split or Trim, which leave the square CV hull of an exact circle and short spans at the cuts.
  * **CVs 0** picks the fewest CVs that keep the curve within **Tolerance** of the original. A fixed CV count is also accepted.
  * Open curves keep their end points exactly. With **Keep End Tangents** they also keep their end directions, so they stay G1 to whatever they meet.
  * Closed curves become periodic splines (smooth across the seam).
  * The fit is least squares on dense samples of the exact curve, with parameter correction and light fairing for even CV spacing. The deviation is checked both ways.
* **Extend Curve** lengthens open curves; the original part stays exact.
  * **Natural** continues the end span's own shape, so a line stays a line and an arc keeps going on the same circle.
  * **Line** adds a tangent straight segment (G1).
  * **Arc** adds a circle with the end's tangent and curvature (G2).
  * **No extra CVs where the shape allows it.** When the extension continues the end span (Natural, Line on a straight end, Arc on an exact arc), the last span itself is lengthened. A line just has its end CV moved, an arc piece keeps its CV count, and a Bezier spline stays Bezier with the same points.
  * **Keep CV Count** covers uniform splines with several spans, which can only be lengthened exactly by gaining CVs. With it on, they are refit with their own degree and CV count, and the deviation is reported.
  * **By Distance** adds that much length. **To Next Curve** extends up to the first visible curve it meets. **To Active Curve** (Object Mode) extends up to the active curve; select that boundary curve last.
  * **End: Auto** uses the selected end point(s) in Edit Mode; otherwise it picks the end nearest the boundary curve, or the 3D cursor.

### Curve tools in Edit Mode

Rebuild, Extend, Split and Trim Curves also work in curve Edit Mode, so the CVs stay visible:
* They edit the splines in place, and Edit Mode's own undo covers them.
* They work on the selected splines: any spline with a selected point, or every spline of the object if nothing is selected.
* Pieces from Split and Trim stay splines of the same object.
* Other visible curves still act as cutters and boundaries. Trim only changes the curves being edited.

### Selecting curves in Edit Mode (CV / Hull / Curve)

Blender's curve Edit Mode picks only CVs. In the tool settings bar (or in the viewport header when that bar is hidden) three modes add picking the lines, like a mesh's Vertex / Edge / Face. They work while a select or transform tool is active (Tweak, Select Box / Circle / Lasso, Move, Rotate, Scale, Transform). Shift+click adds or removes. What a click would pick lights up under the mouse.
* **CV** (the default): a click near a CV is Blender's own. A click on a hull line away from the CVs selects that span's two CVs. A click on the drawn curve selects the whole curve; where the curve runs along its own hull (a straight piece), the curve wins. **Double-click a CV** to select its whole curve. Box and lasso stay Blender's.
* **Hull**: a click picks the nearest hull span (its two CVs; on a Bezier curve, the piece between two points), even right at a CV. A click on nothing deselects.
* **Curve**: a click on a CV, a hull line or the curve selects the whole curve. **Box, lasso and circle** select whole curves: every curve the box touches comes in, whether a CV is inside or only its line crosses it; a deselecting box (Ctrl) takes whole curves out. Switching to Curve turns curves that are partly selected into whole ones.
* The picks are the CVs' own selection, so Edit Mode's undo, the transform tools and the curve tools (Rebuild, Split, Trim...) all see them.

### Soft fillets

**Shape: Soft** (Surface Fillet and Edge Fillet) is a curvature-ramped corner, the kind consumer products and phone icons use: across the fillet the curvature starts at the faces' own (zero on a plane), rises steadily and peaks at exactly **1 / Radius** in the middle. **Radius** is the *minimum* radius, so a soft fillet reaches further along the faces than a circular one of the same radius. Each section is one Bezier span: **G2** is degree 5 with the first 3 CVs on each face's tangent, **G3** degree 7 with 4 (the faces' normal curvature, and for G3 its rate, are put on CVs 2 and 3, so curved faces hold too). The construction is our own (`kernel/softfillet.py`):

* **Ideal curve.** A circular arc of the radius between two curvature ramps: linear in arc length (a clothoid) for G2, smoothstep (its rate zero at the face too) for G3. **Smoothing** is the share of the turn the ramps take: low is close to a circle, 1 has no arc left. G2 holds from 0.1, G3 from 0.5 (below that a single span cannot follow the arc and its curvature bumps on the ramp; G3 then uses 0.5 and says so).
* **The span.** The CV spacings along the two tangent lines (mirror symmetric) are the single span closest to that ideal, fitted with exact foot points. Where a span cannot hold the arc's flat top it would dip in the middle (two peaks); the middle is then held flat instead. Checked from 5° to 175° between the faces: curvature always rises steadily to the middle. Solved on a 0.5° grid of angles and interpolated (cubic), so the sections change smoothly along an edge whose angle changes.
* **Size.** The span's own peak sets where it touches the faces: at 90° and Smoothing 0.6 the rails are 1.69 × Radius from the corner (G2; G3 1.58 ×; a circular fillet: 1 ×). From exact sections (Surface Fillet, and Edge Fillet's sheet-boundary / closed edges, as Chord) each section's ball is sized from its own angle, then corrected so that section's sharpest point has the radius exactly: on a wall through a cylinder (the cylinder curving 1/R = 10 × the fillet's across) the minimum radius holds to 6 digits, with the curvature at the rail matching the cylinder's to 6 digits (G2) and its rate going to zero (G3).
* **Edge Fillet on a body** (fillets that end against a face or meet at corners): the kernel's circular fillet, its ball sized from the edges' mean angle, gives the rails, and every fillet strip is rebuilt with soft sections between them (the Class-A rebuild, which then also takes G1 / G2 to the next strip). A box comes out with one-span strips (6 x 2 CVs, degree 5 x 1; G3 8 x 2) exactly G2 to the planes (Continuity Check 0.0000°, 0.00 %). **Fill Corners** (default on): where three or four strips meet, the opening is filled with a **Square**, G2 to the strips around it (Match Neighbours: one 6 x 6, degree 5 patch per box corner), and stitched in, so a solid stays solid. Along the corner seams Continuity Check reads 0° and 0 % except at the three-sided Square's collapsed point, where the patch has no normal. With Fill Corners off the openings stay and the report says how many (fill them with Square G2 by hand). Variable radius and Chord don't apply to Soft.
* **Report.** The measured minimum radius (range over the sections) and the smoothing used, and on a body how many corners were filled. The preview draws the soft sections with the faces taken flat across (exact on planes), the arrow sits on the rail (1.69 × Radius out at 90°).
* Smoothing about 0.6 looks like the familiar phone-icon corner; the measured iOS icon corner is within 1.1 % of its size of Soft G3 at Smoothing 1 (4 % for G2). That curve is a pixel fit that is not G2 itself (its published Bezier constants kink 2.45° between segments), so it is only a visual reference.

### Class-A fillet patches

The kernel fillets a straight edge with a light exact face (a rational arc across, 2 CVs along), but a curved edge gets one **dense** face: degree 3, knots that cluster where the edge's curvature changes, and a 4-span cubic stand-in for the arc (for example 7 x 65 CVs along a U-bend). With **Class-A Patches** on, every such face is rebuilt (`kernel/classa.py`, in the worker):

* **Exact sections.** Each cross-section starts from the true rolling ball: the ball touching both faces, solved from the kernel section. Sections are spaced evenly along the exact geometry, so a symmetric fillet is sampled symmetrically. **Circular** becomes a rational quadratic arc: end CVs on the contact curves, middle CV where the face tangents meet, weight cos(θ/2). **Blend** becomes the kernel's own Blend shape: a degree-5 (G2) Bezier between the same contact points, whose first three CVs run along each face tangent at the kernel's spacing (read from its faces, 0.351 × tangent length at Fullness 1). CV 2 is offset by the face's normal curvature, so G2 also holds on curved faces. Chamfer uses lines. Variable radius uses the kernel's sections.
* **Even and symmetric.** For each patch count, evenly spaced splits are tried first; error-driven splits are used only when even ones miss the tolerance. A mirror-symmetric fillet (detected from the distances within and between sections) keeps mirror-symmetric parameters and splits. Faces are rebuilt simplest first, so a straight run becomes one exact patch (degree 1 along), and the bend takes its G1 / G2 from the patches already built, using their exact derivatives.
* **Fewest patches.** The section CVs are fitted along the edge with one span of degree 3 up to **Max Degree**. Only if that misses the tolerance are 2, 3 ... spans tried, with the knots moved to where the error is and the samples re-parametrised. The result is split into single-span patches, which are C^(degree-1) to each other.
* **Ends.** Where the patch meets another fillet face (a straight fillet kept from the kernel, or a patch already rebuilt), it interpolates that face's section exactly, with **G1** or **G2** (default) across the joint. Each section row may slide along the joint, as the two contact curves of a curved fillet move at different speeds.
* **Checked.** A candidate is accepted when its deviation from the exact sections is ≤ **Tolerance** (default 0.1 mm) and the normal angle to both faces along the rails is ≤ **Angle Tolerance** (default 0.1°). The report gives, per face, kernel CVs → patches, degree, deviation, angle and ends (e.g. `7x65 CVs -> 6 single-span patches 3x7 (dev 8.4e-05, 0.012 deg, ends G2/G2)`).
* **Stitched back.** The dense face is removed, the patches are copied in without a boolean (`blender_ext.append_brep`, so a patch lying tangent on a plane is not imprinted), and the body is stitched within 2.5 x the patch-to-rail gap. Zero-area slivers are dropped. If the result has more open edges than the kernel fillet, or any non-manifold edge, the kernel fillet is kept and the report says why.

A tight bend needs more patches for the same tolerance: the inner contact curve of the rolling ball is an offset of the edge, which no single polynomial span follows exactly. On the U-bend test part (bend radius ~0.3, fillet radius 0.1) a 1 mm tolerance gives 4 patches and 0.1 mm gives 6.

Trim and Fillet run their kernel calls in a **separate worker process**
(`kernel/worker.py`, started with Blender's own Python). The kernel can crash on
some inputs (the surface-surface fillet is documented to), and kernel ops can take
ownership of their input surfaces. In the worker a crash only fails the command,
and every job works on fresh copies. Trimming an object removes its construction
history. Trimmed and multi-face objects can be picked by their real B-rep edges
(G0 only).

* If curves are selected, a tool uses them. **Alt+click** the tool (or start it with
  nothing usable selected) to **pick** curves or surface edges in the viewport:
  LMB pick, Shift+LMB keep picking, Backspace undo, Enter finish, Esc cancel.
* After a tool runs, its settings stay editable in the **Adjust Last Operation** panel (F9).
* **Construction history** (Alias-style): results follow their inputs while you
  move them or edit their CVs. **Delete History** freezes them.
* Input curves can be Blender **Bezier**, **NURBS** or **Poly** splines. All of them
  convert exactly, including every NURBS knot mode (uniform, endpoint, Bezier, cyclic,
  rational weights). For example, the NURBS circle primitive becomes a true circle.
  The add-on rebuilds Blender's knot vector and clamps it by knot insertion. It
  matches Blender's own curve to about 3e-7 (float precision).
* Inputs read the object transform from its stored location/rotation/scale and
  parents, not the runtime `matrix_world`. That value can be stale right after the
  undo the F9 panel does on every change.

## Pattern (Linear / Circular / Path)

**Pattern** (Create Surfaces panel, From Surfaces, under Offset and Thicken; it works on curves too) copies the selected NURBS objects and curves in a row, grid or block (linear), around an axis (circular) or along a path. It starts as a path pattern when a curve is active with other objects selected (the curve is the path), otherwise in the mode used last; **M** switches. Each copy is a NURBS object (or curve) of its own carrying the exact geometry, so it exports to STEP, shows its CV net and can be picked, trimmed and joined like any other. Blender's **Array** modifier copies only the display mesh, which has no B-rep behind it, so use it only for plain meshes. A copy is the source's B-rep under another matrix: it takes the source's mesh as is, so making 24 copies costs no extra tessellation (only when the source changes is each copy rebuilt).

The pattern is laid out on a **widget**: a centre with X (red), Y (green) and Z (blue). Linear and circular show it; the copies show as a preview.

- **Drag the centre** to move the widget. It snaps like the sketch tools (ends, middles, face centres, CVs, edges; **Ctrl** the grid, **Alt** no snapping). Dropped on a flat face, the widget lines up with that face: its Z is the face's normal. **C / W / B** put it on the 3D cursor, the world origin or the middle of the sources.
- **Number keys set the count**: of the active arrow (linear) or of the pattern (circular, path). **+ / -** (or Up / Down) one more or fewer.
- **Tab** switches the number keys to the value instead (the active arrow's spacing, the angle, the path distance; unit letters work: `25mm`), Tab again back to the count.
- **M** switches linear / circular / path (a curve that was the path is copied with the rest in linear and circular). **Enter**, or a click away from the widget, makes the copies; **Esc** cancels.

| | Linear | Circular | Path |
|---|---|---|---|
| handles | an **arrow** per direction X, Y, Z: drag one out to the last copy along it (an unused arrow pulled out starts with 2); the **ring** turns the widget about its Z, so the rows run at an angle | the **arrow round the axis**: the angle the copies spread over (**Ctrl** 5° steps) | the **arrow along the path** to the last copy |
| directions | one, two (a grid) or all three (a block); **X Y Z** make that arrow the active one | the axis is the widget's Z through its centre; **X Y Z** turn the widget so its Z is that axis | from the path point nearest the source on |
| **A** | pick a line or edge for the widget's X | pick a line, straight edge or **circle** (a hole's edge): the centre goes to the circle's centre, Z along its axis | pick the path: a curve or a surface edge. With a curve active among the selection, it is the path |
| **E** | spacing between copies or length from first to last (the copies stay put) | - | spacing or length; 0 = to the path's end (a closed path: evenly all the way round) |
| **R** | - | rotate copies on / off (off: moved round, kept upright) | follow the path on / off (off: only moved) |
| **F** | the active arrow the other way | the other way | - |

Linear starts with every spacing at 0 (the copies sit on the original until an arrow is dragged; **L** brings back the last spacings). A full 360° spreads the copies evenly (none lands on the original); less than 360° puts copies at both ends. Along a path, the copies keep the source's offset from the path and turn with it (a rotation-minimising frame, as a sweep's).

With construction history every copy follows its source: change the source's shape (CVs, its own history) or move it and the copies update; along a path they also follow the path. A copy moved by hand keeps its offset. The Feature panel of a copy shows the pattern with **Edit Pattern** (the same widget, starting from the pattern as it is: more or fewer copies, another spacing; existing copies are kept and moved, extra ones deleted) and **Select All**. The original lists the patterns made from it too (**Patterns made from this object**, one line each with its own Edit Pattern and Select All), so a pattern can be changed without finding one of its copies. **Bake** on a copy makes it a plain object that no longer follows. Without history the copies are plain objects from the start.

## Mirror (Mirror Copy / Make Symmetric)

**Mirror** (next to Pattern; it works on curves too) mirrors the selected NURBS objects and curves across a plane. The plane is the widget's: its centre and its Z (the normal). It starts on one of the three planes of the work plane (or the world) through its origin: for a copy the plane the objects come nearest to touching (the middle of a half model), to make them symmetric the plane they are most centred on; ties go to Y = 0, Alias's default. Drag the centre to move the plane (it snaps; dropped on a flat face the plane becomes that face's), drag the arrow to slide the plane along its normal, **X Y Z** puts the normal along that axis, **C W B** puts the plane through the 3D cursor, the world origin or the objects' middle, **Tab** types the offset. **S** switches the output:

* **Mirror Copy**: a mirrored copy. It is a pattern copy (the Feature panel's **Edit Mirror** moves the plane; **Select All** selects copy and original) and follows its original with construction history. The copy is turned over so it faces out as the original does (a solid stays a solid with its faces outward), and its object matrix stays proper (no negative scale), so it exports, booleans and joins like any other object. Model one half, put **Symmetry Plane** continuity (Align, Blend, CV Curve) on the edges that meet the plane, and the copy joins the half smoothly.
* **Make Symmetric** (as Alias's Symmetric Modeling): one object whose CVs come in mirrored pairs. Each CV is paired with its twin across the plane (a curve: CV i with CV n-1-i, a closed curve with the shift that fits; a Bezier point's left handle with its twin's right one; a surface: its CV rows reversed along U or V, whichever fits the mirror) and the master half is copied onto the other; a CV that is its own twin (the middle of an odd count) is put on the plane. The master half is the start of the curve or the first rows; **F** (Flip Master Side) keeps the other half. The preview shows the master half and its mirror image. After that, in Edit Mode (Tab on a curve, Edit CVs on a surface) a CV that moves moves its twin to its mirror image, whatever moved it: G / R / S, proportional editing, snapping, typed values. When both twins move the selected one leads (both selected: the master side), the middle CV slides only within the plane, and the twins of the selected CVs are marked with a blue dot. Undo and redo leave the pairs mirrored. The plane is kept on the object (it moves with it) and drawn while the object is selected; the Active Object panel shows it with **Remove Symmetry** (the CVs stay where they are). A trimmed surface keeps its trims and a surface with history gets a CV Tweak step, as with Edit CVs. The knots must read the same both ways (Endpoint and uniform knots do); otherwise the result is only nearly symmetric and the tool says so.

## Unroll and Flow (sheet metal)

**Unroll Surface** and **Flow Along Surface** (Create Surfaces panel, From Surfaces, under Pattern) work as a pair, like Rhino's UnrollSrf / FlowAlongSrf: model the part in 3D, unroll it into a flat pattern to cut from sheet, draw holes, slots or lettering on the flat pattern, and flow them back onto the 3D part where the sheet will be bent to.

**Unroll Surface** lays the selected NURBS surfaces out flat:

* **Developable surfaces** (planes, cylinders, cones, extruded curves, bent strips, folded sheets with sharp creases) unroll exactly: the flat sheet has the same lengths and area as the surface (to about 1e-6 of its size). The report says **exact**.
* **Joined faces** (a box, a sheet-metal part made of flats and bends) unroll face by face, each face placed against a face already laid out along their shared edge, so the pattern stays in one piece with the **bend lines as edges**. A face that would overlap the layout, or whose shared edge isn't the same curve once flat (a cone's round cap against its unrolled side), starts a new piece, beside the others. A box unrolls into the usual cross.
* **Trims and holes** come along: a pipe cut at an angle unrolls into the classic sine-curve pattern, and a hole in a cone stays a hole in its pattern.
* **Curves Along:** selected curves lying on the surface (Iso Curve, Project, Offset on Surface, Duplicate Edge results) are unrolled with it, onto the sheet. A curve crossing a cut of the layout comes apart there.
* **Place:** **Beside** puts the pattern flat on the ground (the object's lowest Z) beside the object, the outside of the part facing up. **Touching** puts it in the surface's tangent plane at its middle, touching it there.
* **Not developable** (a sphere, a double-curved panel): the report gives the largest stretch. With **Relax** (on) the pattern is flattened with the least stretch (an approximate pattern, like Rhino's Smash); otherwise it is laid out from the middle of the surface outward.
* The surfaces are measured as they are (zero thickness): for a bent sheet of real thickness, unroll the surface on the sheet's neutral axis (an Offset by half the thickness, or your K-factor's share).
* With history the pattern follows its surface: change the cone's radius and the pattern is laid out again.

How it works: the flat map is built from the surface's own geometry (the length and the turning of its iso lines inside the surface, the angle between them), integrated with Gauss-Legendre rules in every knot span, so a developable surface is unrolled without any search or fitting of the 3D shape. The flat sheet is a B-spline over the **same (u, v) domain** as the face it came from: every point of the sheet knows the point of the 3D face it belongs to.

**Flow Along Surface** bends curves and NURBS objects from a **base** surface onto a **target** surface. Select the geometry and the base, then the target last (active); the F9 panel shows **Base** and **Target** to change them.

* **Fold back:** when the base is a pattern made by Unroll from the target, every flat face goes to the face it was unrolled from at the very same (u, v): a circle drawn on a cone's pattern lands on the cone with the same length, a disk with the same area, a line drawn across a box's cross folds over the box with corners at the bends. **Fold Back** (on) is used whenever it applies.
* **General:** otherwise a point's place on the base, as a share of the base's (u, v) domain, is the same share of the target's (both untrimmed): usually the base is a flat rectangle the pattern was drawn on (drawn with Plane, or a Plane primitive). **Flip U**, **Flip V** and **Swap UV** turn the target's directions round when they run the other way. Note that the (u, v) of a target need not run evenly (an exact circle's does not), so a straight line can come out a little uneven.
* The height above the base (along its normal) is kept above the target. Curves are refitted within 1e-5 of the size (their corners kept); surfaces are refitted over their own (u, v) with their trims, so a flowed solid is still one body.
* **Rigid** moves and turns each object as a whole instead of bending it (rivets, bosses, logos that must not deform).
* The originals stay; the results are new objects, selected. With history they follow the geometry, the base and the target.

## Emboss on curved solids

**Emboss** (Surface Edit panel, Solids) puts lettering and logos on a solid's face of any shape. The profiles are extruded into a prism from Overlap behind the surface to Height in front of it, the prism is laid on the body, and it is joined to it or cut from it.

* **Project** is the quick one: draw the lettering on a plane facing the part (a work plane in front of it, above it, beside it) and run Emboss with the curves and the body. Every point of the prism moves along the plane's normal by the distance to the body on its line, so the walls stay straight and parallel to that direction and the top follows the surface at Height. Lettering thrown at a steep slope is stretched in the slope's direction (as a shadow is).
* **Wrap** keeps the lettering's size on the surface: **Unroll** the body (or its face), draw on the flat sheet where the lettering should go, select the curves and the sheet, then the body. The sheet folds back face by face at the same (u, v), the height goes along the outward normal. On a developable face (cylinder, cone, bent sheet) it is exact; on a double-curved one the lettering is stretched by the unroll's relaxed stretch where it lies (a dome stretched 69 % at its corners still kept a 0.6-tall L within 2 % of its area in its middle).
* **Place** is for small marks that must not bend at all.

How the side is chosen: a step along the profiles' normal from their centre is followed through the map onto the body, and the prism goes the way that step leaves the body, so the result is outward even where the surface's own normal points in (a lofted sheet thickened downward, the sheet Unroll makes from a sphere faces −Z).

Times: an L and a 48-sided O projected onto a lofted dome take about 3.5 s; an L and a ring of true circles wrapped from the unrolled dome about 1.7 s.

### How the analysis overlays are meshed

Zebra, draft angle, the matcaps and the curvature map draw on a mesh of their own, finer than the display mesh, with the exact normal (and curvatures) at every vertex: the display mesh's coarse triangles would bend stripes and colours. That mesh used to come from the kernel's tessellator at 1°, which costs about 5 µs per triangle: a SubD body became 400k-1.2M triangles and 4-8 s, the curvature map 2 s (its curvatures were computed vertex by vertex in Python). Now it is built in numpy straight from the control nets (`surfeval.py`, `anamesh.py`):

* **Untrimmed faces** (every face of a SubD or Mesh to BREP body, most single surfaces) are a grid in (u, v). Each knot span gets as many steps as its normals turn (the Quality angle), its sag needs (Chord), its length needs (no edge over 1/30 of the body) and its two border curves turn (so a flat face with a curved outline is covered to its edge). The whole grid is evaluated with two small matrix products per derivative. C0 knot lines split it, so each side of a crease keeps its own normals.
* **Trimmed faces** are tessellated alone by the kernel at a coarse setting (its folds, cracks and needle triangles repaired as for the display mesh), then every triangle is split in (u, v) as finely as its normals' spread and its length ask; an edge is split as finely as the finer of its two triangles wants, so neighbours meet point for point, and every new point is evaluated exactly.
* Normals point outwards (the face's outward normal on the body), the per-face set-up is kept per body and revision, so the curvature map after the zebra, or another quality, takes 30-40 ms. The meshes are kept until the body changes, so switching an overlay off and on is instant.

Measured (first show after an edit, mesh and GPU upload):

| Body | Zebra before → now | Curvature map before → now |
|---|---|---|
| SubD cube G1, 38 bicubic faces | 8.1 s → 0.13 s | 2.3 s → 0.08 s |
| SubD cube G2, degree-6 star faces | 5.0 s → 0.12 s | 1.9 s → 0.09 s |
| SubD cylinder G2, 48 degree-6 faces | 4.0 s → 0.14 s | 2.2 s → 0.12 s |
| Vase, 7 faces (3 trimmed) | 2.4 s → 0.29 s | 0.83 s → 0.09 s |
| Pipe (one surface, 65 x 9 CVs) | 14 s → 0.07 s | 1.6 s → 0.01 s |

The normals are as exact as before or more so: the angle between the interpolated and the exact normal inside the triangles stays below 0.1° at the 99th percentile (0.03° on the degree-6 SubD cube), and a sphere's poles are right (the kernel's mesh had a 33° error there).

## Texture

Both tools texture the NURBS object itself: it stays a NURBS object you can keep editing, and the materials
and UVs are written again after every rebuild. Press Z › Material Preview to see them.

### Plywood

In the **Texture** panel, next to Face Material. It textures a bent plywood shell for rendering the way the real part
looks: a veneer on the front, one on the back, and the band of plies where the shell is cut along its rim. Select a
NURBS solid of even thickness (a sheet after **Thicken**, a chair shell, a bent panel) or a plain mesh shell and click
it.

* **Texture: NURBS Object** (default) puts the materials and UVs on the NURBS object's **own B-rep faces**. It stays a
  NURBS object you can keep editing: every rebuild (a history edit, CV moves, a new display detail) sorts the faces
  again and writes the UVs again, and the materials stay. **Render Mesh** meshes it like BREP to Mesh (Light, at the
  Detail you choose) into a separate "‹name› Plywood" and hides the NURBS object, for export, modifiers or texture
  painting. A plain mesh is **textured in place** (its own mesh, before its modifiers).
* **Which face is which:** a face is veneer when the other side of the shell lies straight behind it, at the
  thickness, facing the other way. Everything else is **edge**: the rim walls, and a rounding or chamfer of the rim
  too (sanding a rounded edge shows the plies, so it gets them). The veneer faces fall into two sides; the **front**
  is the one facing up (most of its area). **Swap Sides** turns that round.
* **Veneer UVs:** each side is unwrapped as **one sheet**, as a veneer is bent over the form, so the grain runs on
  across patch boundaries and over the bend. The unwrap keeps the sheet's true size (in metres) and its shape as
  closely as a doubly curved sheet allows; the sheet is turned so the grain runs along its length, and **Grain Angle**
  turns it from there (90° across).
* **Edge UVs:** u is the length along the rim in metres, v the **depth through the shell, 0 at the front, 1 at the
  back**, measured from both veneers, so a rounded rim spreads the plies over its curve. Any edge texture whose height
  is the full ply stack fits exactly, whatever the thickness. A hole's rim is its own strip.
* **Materials** (slots 0 Front, 1 Back, 2 Edge):
  * **Front Veneer** and **Back Veneer**: a procedural figure with fibres along u in the chosen wood (Birch, Beech,
    Maple, Ash, Oak, Walnut, Teak), satin lacquer. **Back Veneer: Same as Front** puts the front's material on the
    back. **Veneer Image** uses a photo instead (its grain along the image's width), **Image Width** the length of
    veneer it covers.
  * **Edge**: **Plies** stripes across v (0: about one per 1.5 mm, odd), the outer two in the veneers' woods, the
    core plies alternating long grain and cross grain in the **Core Plies** wood, dark **Glue Lines** between. The
    count, glue width and thickness are the object's `ply_count`, `ply_glue` and `ply_thickness` properties, so you
    can change them without running the tool again. **Edge Image** uses a photo of a ply edge instead: its height spans the
    thickness, its width runs along the rim in proportion.
  * **Your own materials:** **Own Front**, **Own Back** and **Own Edge** put a material of yours in that slot. A
    material you drop into one of the three slots yourself (Material Properties) is kept by later runs too; empty
    the slot to get the tool's own back. The tool's materials are made once and kept, so your edits to them stay.
    The UVs above are what your textures map to: real-size veneer sheets, and the edge band's 0–1 depth.
* **Run it again** on the result (the textured NURBS object, the render mesh or its NURBS object) to change the
  settings: the last run's settings come back for anything you don't set. The Adjust Last Operation panel shows the
  thickness found and how many faces went where.
* A shell it can't read (a lone sheet, no faces opposite each other) is refused with a message.

### Face Material

In the **Texture** panel, and in **Material Properties** under the slot list of a NURBS object (**Assign to Picked
Faces** / **Assign to All Faces**, **Clear**, ✕). It gives B-rep faces a material of their own, as Edit Mode's Assign
does for a mesh: pick faces in **Face** mode, choose a slot in the material list, click Assign. With no faces picked,
it assigns to all faces.

* The faces keep their material through every rebuild: each one is stored with a point on it and found again however
  the rebuild numbers the faces. A face rebuilt somewhere else loses it.
* The object gets **UVs in metres**: each face is its own island, unwrapped at its true size and turned so its long
  side runs along u, the islands laid side by side, so a tiling texture keeps its scale from face to face. On a
  Plywood object the veneer sheets and the edge band keep their Plywood UVs, and an assigned face only changes material
  (an inlay, a painted patch).
* The display mesh carries a face attribute `brep_face` (the B-rep face of every triangle), for shader tricks and
  selection.
* **Clear** puts the picked faces (all, when none are picked) back to slot 0, or to their Plywood material. **✕**
  (Remove Texture) drops the per-face materials, the Plywood sorting and the UVs; the slots stay.
* Texturing costs a little at every rebuild (about a third more on a chair shell of 35 faces). Untextured objects
  don't pay it.

## Convert

### BREP to Mesh

Under Convert, and in Blender's **Object › Convert › Mesh (NURBS Proto)**. It turns the selected NURBS objects into plain
mesh objects for rendering, texturing and animation. A dialog shows the settings first (**Convert** runs it); they stay
adjustable afterwards in the Adjust Last Operation panel. Each object is meshed afresh at the detail you choose, not
copied from the display mesh. The new object is called "‹name› Mesh"; it keeps the NURBS object's place, parent, collections,
materials and modifiers. The NURBS object stays with its history, hidden in the viewport and in renders (switch
**Hide NURBS Objects** off to keep it shown).

* **Mesh: Light** (default) gives every face the lightest mesh that still shades like it:
  * a **flat face is one n-gon**; a flat face with holes becomes a few n-gons, as Blender's faces can't have holes;
  * a **curved face is a grid of quads** along its (u, v) lines, only as dense as the surface bends in each
    direction. A cylinder's side is one strip of long quads, a box 6 quads, a sphere quads with triangle fans at its
    poles. Where a trim crosses the grid, triangles meet the edge.
  * The lines are **spread evenly by how much the surface bends** (each step's share of the angle and chord it
    needs), so a symmetric shape gets a symmetric mesh and the spacing changes smoothly with the curvature.
  * An **untrimmed face's grid sets the points on its edges**, so it meshes as pure quads: a loft's two rails get the
    same columns, and a side split into several edges gets a grid line through each vertex.
  * A NURBS cylinder at Medium is 2 n-gons and 48 quads (360° / 7.5°); its display mesh is 6,332 triangles.
* **Mesh: Triangles**: the same mesh split into triangles, for game engines and glTF.
* **Detail**: **Low** (chord 0.4 % of the object's size, 15°), **Medium** (0.1 %, 7.5°), **High** (0.025 %, 3°) or
  **Custom**. Chord is the largest distance from the mesh to the surface; Angle the largest turn between neighbouring
  edges or grid lines. Every change re-runs in the Adjust Last Operation panel, which shows the faces (n-gons, quads,
  triangles), vertices, the triangles a renderer will draw and the display mesh's triangles for comparison.
* **Welded:** every B-rep edge is sampled once and both faces use its points, so a joined body or a solid comes out
  closed. Separate objects stay separate meshes; join their surfaces (Surface Edit › Join) first for one closed mesh.
* **Shading:** each corner gets the exact normal of its own face, so creases stay sharp and tangent joins (fillets)
  smooth. Edges between faces bending more than 30° are marked sharp as well (for modifiers and Smooth by Angle).
* **UVs:** one island per face from its (u, v). **Real Size** (default) is in metres, so a texture keeps its scale
  from face to face; **0-1 per Face** fills the UV square with every face; **None** leaves the UV map out. **Pack
  Islands** lays the islands side by side in 0-1 for baking. B-rep edges are UV seams, so Unwrap starts from them.
* **brep_face** (an integer face attribute) names each polygon's B-rep face: select by it in Edit Mode to give a face
  its own material.
* **Join** makes one mesh object of all the selected NURBS objects.

### Mesh to BREP

Under Convert, and in Blender's **Object › Convert › NURBS Body (NURBS Proto)**. It rebuilds the selected mesh objects as
NURBS bodies you can keep working on, by recognising what was modelled and making it again with the kernel, not by
copying facets:

* **Flat faces** become planes: coplanar facets merge into one face, however the mesh triangulated or split them. A
  point a knife line or a Boolean left in the middle of a straight edge doesn't count. A flat four-sided face becomes a
  bilinear patch on its corners with no trim; other planes keep the kernel's planar face, its plane cut down to the
  trim's uv box (also beside the fillets and hole cuts, and when the history re-runs a fillet).
* **Bevels** with a round profile (Profile 0.5, Ctrl+B or the Bevel modifier, 2 segments or more) become **fillets** of
  the bevel's radius: the strip's vertices are fitted with a circle, and the fillet must touch both faces beside it.
  The body is rebuilt with sharp edges and those edges rounded with the kernel's rolling-ball fillet, so the fillet is
  exact and G1 to both faces, and where three bevelled edges met there is a smooth corner. One bevelled edge, two at a
  corner, three at a corner and all twelve of a box all work. A chamfer (1 segment) stays a flat face.
* **Boxy bevels** (Profile above 0.5) become exact strips of the bevel's shape: Blender's profile is a superellipse,
  and the converter reads its exponent and setbacks from the mesh (the report gives the Profile value, e.g. *1 bevel
  profile 0.75 w 10 cm*). The strip is the profile swept along the edge, a B-spline within 0.002 % of the bevel's width
  of the true curve, meeting both faces with matching tangent and curvature (G2). A boxy bevel needs **4 segments or
  more**: with fewer, any polyline fits some profile, so it keeps its facets. Its first segments may lie almost flat on
  the faces; they are found and used anyway. From about Profile 0.95 Blender makes a square corner, and that is what
  converts. A boxy bevel that ends on flat faces (one edge, parallel edges, any end face) or where two boxy bevels
  meet in a **mitre** (two bevelled edges at a box corner, all four edges round a top) is exact.
* **Free-form patches.** What is smooth but not one of the shapes above becomes free-form patches: where three boxy
  bevels meet at a corner, all edges of a box bevelled boxy, a bevel swept along a curved edge (an end face's outline
  bevelled after a boxy bevel), and the bevels running into them. The smooth quad grid is cut into rectangular blocks
  at its irregular vertices, and each block becomes a C1 bicubic B-spline through the mesh's vertices. A vertex has one
  tangent for every curve and patch through it, so patches share their edges exactly with each other and with the flat
  faces, and meet them tangentially (G1, the normals agree to within 0.01°) wherever the mesh is smooth; only at the point
  where three patches meet (the middle of a three-bevel corner) the normals differ by a few degrees (about 3° with 12
  segments, 11° with 6). The report counts them (*6 planes · 9 free-form patches*). A round fillet that runs into a
  patch becomes part of it. Patches follow the mesh's vertices, so they are as fine as the bevel's segments; the exact
  shapes above stay light.
* **Round holes** (a Boolean with a cylinder, for instance) become exact cylindrical holes of the mesh's diameter,
  through or blind (the flat bottom at the hole's depth), in any direction. Knife lines and bridges between holes are fine.
  A hole cut through an edge or a corner (a notch) is one exact cylinder face, ruled between rational arcs on its end
  planes; pieces on one circle are joined, and facets the Boolean cut short at its sides are taken in.
* **Cylinders** become exact cylinders whose caps are trimmed planes.
* The fillets are **Edge Fillet steps** in the body's history, one per radius, so you can change the radius in the
  Feature panel afterwards.
* The report says what was found, e.g. *6 planes · 3 fillets r 6.29" · 1 hole ⌀ 2'*.
* Anything not recognised keeps its facets as flat faces (an icosphere becomes a body of its flat facets). If the rebuilt
  faces don't close into a solid, the whole body is made of the mesh's flat regions instead, and the report says so. An
  open mesh becomes a sheet.
* The settings (Adjust Last Operation panel): **Fillets**, **Holes and Cylinders** (each off keeps those facets),
  **Tolerance** (how far points may be off a plane or circle, as a fraction of the object's size: raise it for imported
  or scanned meshes) and **Hide Meshes**.
* Modifiers count: a Bevel or Boolean modifier is converted as you see it. Apply scale first: under a non-uniform scale
  Blender's round bevel is elliptical and stays faceted.
* Not yet: fewer, larger patches (neighbouring blocks merged), rounded hole lips, countersinks, holes at an angle to a face,
  bosses on faces, chamfers as editable steps, bevels of different widths meeting at a corner, custom bevel profiles,
  and boxy bevels as editable steps (the kernel has no superellipse fillet, so their shape is fixed).

### SubD to BREP

Under Convert, and in Blender's **Object › Convert › NURBS Body from SubD (NURBS Proto)**. It turns the selected
Subdivision Surface models into NURBS bodies of the smooth surface you see, built from the control cage (the mesh
before its Subdivision Surface modifier), with **one face per cage face**.

* **The SubD itself where it can be.** Catmull-Clark's surface is a bicubic B-spline wherever the mesh is regular,
  so every face without a star point (a corner where 3, 5 or more edges meet) is **one bicubic span**, 16 CVs: exactly
  the SubD surface, joining its neighbours with matching curvature (C2).
* **Higher degree at the star points.** No bicubic faces can be the surface there and also join smoothly, so a face
  with a star corner becomes **2 x 2 polynomial pieces**, evenly spread like the subdivided cage (knots 0, ½, 1) and
  smooth across its own middle lines: **degree 6 in G2** (12 x 12 CVs), **degree 5 in G1** (10 x 10 CVs, the lighter
  net); G2 can also be **degree 5** (**Degree** *5 · Lighter*: G1's net, still exactly G2). It is fitted to the SubD, then moved as little and as smoothly as possible until it joins every neighbour
  **exactly**: the normals agree all along each edge (G1) and, in G2, the curvature too, right to the star point.
  No extra knots, no flattened points: the faces bend through the star point as the SubD does.
* **G1 is G1, G2 is G2:** Continuity Check reads G1 0.000° and G2 0.00 % on every edge of a jack (3-, 5- and 6-edge
  star points), a boot (creases, corners) and a cylinder with 8-edge poles, star points included. In G1 the faces by
  star points are only tangent: their curvature may differ across edges there.
* **Light:** the jack is 2,792 CVs in G1, 3,936 in G2; the boot 2,308 and 3,232. G2 at degree 5 has G1's count:
  2,792 and 2,308, about 30 % fewer than degree 6. (Lower degrees than 5 cannot join
  G1 at 5-edge star points without bending their edges there into near-straight curves: they would leave the SubD
  by about 1 % of the model's size.)
* **Close to the SubD surface:** exactly on it on the bicubic faces; on the others within about 0.15 % of the
  model's size in G2 (the jack 0.11 %, the boot 0.07 %) and 0.25 % in G1 (the jack 0.24 %, the boot 0.06 %). G2 at
  degree 5 stays about as far as G1 (the jack 0.24 %, the boot 0.08 %): twice as far as degree 6 by star points. Next to a star point with 5 or more edges the SubD's own curvature
  grows without bound; there the faces stay a little smoother than the SubD.
* **Speed:** the jack about 1.3 s in G2 (1.0 s at degree 5, 0.5 s in G1), the boot about 1 s (0.75 s, 0.5 s), on
  Apple Silicon. G2 starts from the G1 solve (one linear step) raised to its degree, which halves its steps. The joins
  are one sparse solve per step (Apple's Accelerate on macOS; Windows and Linux use a slower solver, a few times longer).
* **Fast** (G2, off by default): each star point's first ring of CVs is shaped directly (one curvature shared by
  all its faces, so G1 and G2 hold there by construction) and held, and the solve does only the rest: one step fewer
  and a smaller system, about a third faster (the jack 3.3 s instead of 5.1 s with the Windows / Linux solver, 0.53 s
  instead of 0.78 s on Apple Silicon). Still exactly G2. How close it stays depends on the cage: the jack and the
  boot come out closer to the SubD (0.09 % and 0.05 %), a plain cube and a cylinder with 8-edge poles about 1.5 to
  2 times as far as without it. Cages with triangles or n-gons ignore it.
* **Local Re-solve** (on by default): converting the same SubD again after moving some cage vertices solves
  again only the faces whose surface moved, one layer of faces around them and every face around a star point they
  touch; all other faces keep their CVs from the last conversion, and every join stays exact. On a 152-face jack
  (the jack subdivided once) moving one vertex re-solves 34 of its 80 star faces: the conversion takes 1.6 s
  instead of 4.2 s on Apple Silicon. The result differs from a full solve by a few hundredths of a percent of the
  model's size, mostly near the moved vertex. On small cages (most faces near every vertex) all faces are solved
  again, still starting from the last conversion: the jack (38 faces) in 0.36 s instead of 0.76 s. Changed faces
  or creases, other settings, n-gon cages and a local solve that does not close solve it all from scratch. The summary says how
  many faces were solved again. Each Blender session remembers only the last conversion of each object.
* **Live Link** (on by default): the body keeps its construction history and follows its SubD, as Alias' SubD
  bodies do. Move cage vertices (in Object Mode or while editing the mesh in Edit Mode) or change creases, and the
  body is built again on its own, with Local Re-solve, so only the faces near what moved are solved. Trims and fillets
  made on the body are applied again on top: a SubD cut by a surface stays cut where the surface is while its cage
  changes. Live rebuilds skip the join and distance measurements (convert again to see them), and the body is
  built by one kernel worker kept running (no start-up per rebuild). A rebuild of the jack or the boot takes about
  0.5 s on Apple Silicon, Peter (50 faces) about 0.9 s. **SubD Wait** (History panel, 0.3 s by default): the
  body is built again once the cage has been still that long, not on every step of a drag, so dragging stays smooth
  and the body catches up when you stop (0 rebuilds right away, as other features do). **Pause Rebuild** holds
  every rebuild back until you press Rebuild: move several vertices, then build once. To edit
  the cage, show the SubD again (Hide Meshes hides it). The body is built in the SubD's object space and stays where it
  was made: moving the SubD object does not move it. **Bake** (Delete History) cuts the link.
* **It asks first:** a dialog with **Continuity** (G1 or G2; G2 by default), in G2 **Degree** (*6 · Closer*, the
  default, or *5 · Lighter*) and **Fast**, **Local Re-solve**, **Live Link**, **Angle** and **Curvature %** (G2: a join further off than these is reported), **Boundary
  Smooth** (see Open borders) and **Hide Meshes** (the SubD objects stay, hidden in the viewport and in
  renders); **Convert** runs it. The same settings stay in the Adjust Last Operation panel afterwards.
* A cage without star points or odd creases (a torus) becomes exact faces of 16 CVs.
* **Creases** (edge crease 1.0) become sharp edges along the SubD's own crease curves: each side follows its own
  surface, and the smooth faces around a crease's star point join exactly within their side.
* **Open borders** stay open (a sheet), smooth along the SubD's own border curves. A border running straight past a
  vertex is no star point: the faces there stay bicubic. **Boundary Smooth**: *Per Object (its Modifier)*, the
  default, converts each object as its own Subdivision modifier's Boundary Smooth says; *All Objects: Smooth All* and
  *All Objects: Keep Corners* set it for every selected object, whatever their modifiers say. Smooth All rounds the
  border's corners (a vertex of one face, a star point), Keep Corners keeps them where the cage vertex is, as
  Blender's modifier does. Blender only approximates a rounded corner: at the modifier's default **Quality** 3 its
  mesh sits up to about 0.15 % of the model's size off the true SubD surface there (the body is on the true one).
  Raise Quality and the two agree: 0.003 % at 6, the slider's top, and 1e-5 % at 10, which you reach by typing it
  (double-click the field, type 10). Star points and kept corners agree at any Quality. With Keep Corners a grid
  (a sheet without star points) becomes bicubic faces of 16 CVs only, Blender's SubD exactly: SubD as a stand-in
  for NURBS surface modeling, each cage face one Bezier patch.
* **Triangles and n-gons** are split, the quads are not: Catmull-Clark's first step turns an n-gon into n quads, and
  each of those becomes a face, while every cage quad stays one face (its four quads after that step, joined). A
  quad's side next to an n-gon then meets two of its faces, a **T-junction** at the side's middle, and the faces join
  exactly there too (G1 0.000°, G2 0.00 %). The surface is the same SubD. A model with two pentagons and 21 quads
  becomes 31 faces (4,464 CVs in G2) instead of 94 (12,512); a cylinder with octagon caps 24 instead of 48. Bigger
  faces by star points stay a little further from the SubD: that model 0.11 % of its size in G2 (0.23 % in G1)
  instead of 0.03 % (0.06 %); the cylinder 0.13 %, as before. The report counts the T-junctions. If the n-gons can't be
  joined this way, every face is split by one subdivision step, as before, and the report says so.
* The report gives faces, how many are of the higher degree, CVs, the largest angle across an edge (and at the star points),
  in G2 the curvature difference, and how close the faces stay to the SubD surface, e.g. *38 faces · 26 of degree 6
  by the 22 star points, the rest one bicubic span · 3,936 CVs · G1 within 0.000° · G2 within 0.00% · within 2.8 mm
  of the SubD surface (exactly on it on the one-span faces)*.
* Modifiers other than the Subdivision Surface count (a Mirror, for instance). Creases below 1.0 are treated as smooth.
* Not yet: partial creases (below 1.0).

### Fit to Scan (the Scan panel: Cage from Scan, Fit Cage to Scan, Drape Patch to Scan)

Turn a scan (a residual limb, a body part, a product or car part) into exact NURBS that match it: a SubD cage is
fitted so its smooth surface lies on the scan, then **SubD to BREP** makes the NURBS body. Use it to drape a
housing, cover or socket over a scan for 3D printing, or to rebuild a scanned form as editable surfaces.

**Why not Shrinkwrap?** A Shrinkwrap puts the cage's vertices on the scan, but a Catmull-Clark surface pulls away
from its cage: inside it on bulges, outside it in hollows. On a residual-limb scan with a 124-vertex cage, the
surface of a cage whose vertices sit on the scan is about 4 mm inside it on average. Fit Cage to Scan solves for the
cage whose *surface* lies on the scan instead.

**Cage from Scan** (active object: the scan) builds a starting cage for limb-like shapes: **Rings** along the
scan's main axis, **Around** vertices per ring (a multiple of 4), from the closed end up to just below the scan's
open rim (**Length** sets it), the closed end capped with a quad grid (4 star points of valence 3). The rim is the
scan's longest open border: small holes (at a tip, say) don't count, and a large n-gon closing the cut (a lid)
is left out, as it is not scanned surface. With **Fit** on, it is fitted right away. The cage gets a Subdivision
modifier and remembers its scan.

**Fit Cage to Scan** (active object: the SubD cage; the scan is another selected mesh, the scan the cage was made
from, or the **Scan** under Analyze › Scan Deviation) works on any cage you modeled yourself too.

* **Offset**: fit to the scan moved this far out along its normal: a housing's clearance, a liner's thickness.
* **Drape**: one-sided, like a sheet laid over the scan. Where the surface dips into the scan (+ offset) it is pushed
  out at full weight; where it stands outside, it pulls in only lightly, so it bridges folds and hollows instead of
  following them in. On the leg scan with a 3 mm offset, 99 % of the surface keeps at least 2.8 mm off the scan.
* **Smoothness**: evens out the curvature (scan noise, small bumps) at the cost of a looser fit.
* **Hold Spacing**: how firmly the cage keeps its spacing along the surface while it moves.
* **Both Ways**: also pulls the surface towards every part of the scan, so bumps between the surface's samples are
  reached. **Max Distance**: scan points farther away are ignored (0: automatic).
* In Edit Mode only the selected vertices move.
* The report gives the area-weighted RMS distance, the distance 95 % of the surface stays within, and the most inside /
  outside (less the offset).

**Add Loops** (in Fit Cage to Scan; 0, the default, fits the cage as it is) adds edge loops where the surface misses
the scan, one at a time with a fit after each, up to that many; faces whose surface stays within **Tolerance** of the scan get none, and
it stops early once every face does. Each loop is a full loop cut through an edge ring, so the cage stays all quads
with no new star points; a ring stops at an open border, and a triangle or n-gon at its end just gets the new
vertex on its edge. Which ring and which way: after a fit, the deviation left inside a face is what the cage can't
bend to. The part of it that varies along one of the face's directions (each row's straight-line trend taken out)
needs the face cut across that direction; a ring scores the sum over its faces, each in the direction the ring
cuts it. So a ridge running along a limb gets a loop along it, next to the ridge, and a round bump gets loops both
ways. With **Drape** only the places where the surface dips into the scan
count. In Edit Mode only the selected faces are looked at and the unselected vertices stay where they are (the new
loop's vertices still move to the scan, also where the loop runs on past the selection).

On the residual-limb scan, a 10 × 12 tube cage refined with 8 loops (264 vertices) is as close to the scan as an
evenly spaced 22 × 28 cage (652 vertices), 0.40 mm RMS, and its worst spot is 2.9 mm inside instead of 4.5 mm; with
12 loops (394 vertices), 0.29 mm RMS, as close as a 30 × 36 cage (1144 vertices). Four loops take about 10–15 s.

**Trim to Curve** puts the cage's open edge on a trim line: where a housing or socket ends. Draw a closed
curve on or near the scan (Blender's curve Draw tool with Surface depth projects strokes onto it; any curve, set to
Cyclic, or a mesh of edges only works), select it, then the SubD cage, active, and run Fit Cage to Scan: with a
curve selected it trims to it (**Trim to Curve**, on by default; in Edit Mode a new trim line moves the whole cage).
The edge nearest the curve is
moved onto it and the rest of the cage follows, less and less farther from the edge, each vertex keeping its
distance from the scan (so rings moved down a tapering limb come in with it); then the cage is fitted with its edge
held to the line, both ways (the edge onto the line, the whole line reached by the edge), free to slide along it.
Each column of a tube cage goes to the line at its own angle around the limb, so the columns stay upright however
far the line dips. The line is the curve projected onto the scan (out by **Offset**, with a clearance), smoothed
over about 0.5 % of the scan's size: on skin it would otherwise pick up wrinkles (a millimetre over a centimetre)
that a housing's edge should not follow. The cage remembers its trim line: later fits keep the edge on it (**Hold Trim Line**,
shown when no curve is selected), and Add Loops also cuts loops where the edge runs off the line. The report
says how closely the edge keeps to the line along the scan (where on the skin it runs) and in all (that includes
the surface's own distance from the scan there).

On the residual-limb scan, with a line dipping 6.6 cm front to back: the 10 × 12 tube cage trimmed to it fits the
scan at 0.66 mm RMS with its edge on the line within 0.93 mm along the skin; 6 more loops (232 vertices) take
that to 0.36 mm RMS and 0.73 mm. On a smooth synthetic scan the edge keeps within 0.05 mm.

**Drape Patch to Scan** lays one NURBS patch straight down onto a scan, for Class-A style surfacing on a car or
product scan where each patch is a single span of low degree. The active object is the patch's control net: a quad
grid of vertices laid out above the scan (a 6 × 6 grid is one span of degree 5 each way: three CV rows from every
edge, for G0, G1 and G2 to a neighbour later, and no more; more vertices than **Max Degree** + 1 make more spans);
the scan is the other selected mesh or the **Scan** under Analyze. Each CV moves only up or down (**Direction**:
World Z, or the sheet's own normal), so the patch keeps its plan view: footprint, CV columns and parametrisation stay
as laid out. That makes the fit linear and exact: every surface point keeps its place across the direction, the scan's
height under it is found once by a ray straight down, and one least-squares solve gives the CV heights (distances
taken along the scan's normal, so sloping parts count right; walls seen almost edge-on are left out). Robust weights
let go of panel gaps and trim strips; **Drape** makes it one-sided, like a sheet: pushed up wherever it dips into the
scan, only lightly pulled down where it stands above, so it bridges gaps. **Offset** fits that far above the scan,
**Smoothness** calms the CV net (rarely needed: one degree-5 span is already smooth). The result is a new NURBS
object (*Sheet* Patch); run it again on the same sheet and that patch is updated in place. An open scan (a single
panel) whose outside is ambiguous takes the side the patch is draped from as its outside.

On the car scan's hood (a 6 × 6 sheet, 1.5 × 1.1 m): one degree-5 patch is 0.96 mm RMS from the scan, 95 % within
1.95 mm, the rest being the scan's own surface noise; the fit takes 0.04 s.

**Match Neighbours** (G0, G1, G2; default G2) joins the patch to NURBS patches selected with it: every edge of the
sheet that lies along an edge of one of them in plan view (within 5 % of its length on average) is held to it. With
**Snap Edges** the edge's CVs first move across the drape direction onto the neighbour's edge, taking the
neighbour's spacing along it (its edge between the points nearest the sheet edge's two ends, at the same
parameters), and the edge's second and third CV rows shift along, so the CV columns stay straight. Then, with the CVs
still moving only up and down, every continuity condition is linear in their heights: G0 the same point, G1 the
cross tangent in the neighbour's tangent plane, G2 the same normal curvature across the edge (G0 and G1 along a
shared edge already make the rest of the curvature agree). The conditions are solved first, as exactly as they can
hold, and the scan is fitted with the freedom that is left; so on a 6 × 6 sheet a G2 edge sets its three CV rows
and the scan the other three, and two opposite G2 edges leave nothing to the scan. The report lists each matched
edge with its gap, normal angle and curvature difference. Exact where the neighbour's edge (or the part the sheet
covers) is one span of degree 5 or less: measured on the two NURBS surfaces, gaps of 1e-15, angles of 1e-6° and
curvature differences of 1e-12 %, also against a degree-3 neighbour whose edge the sheet covers only part of. At a
corner where two matched neighbours meet, exact G2 also needs the neighbours' twists to agree there; in the tests it
stays within 10 µm, 0.04° and 0.2 %. The patch's sheet remembers its neighbours for the next run.

On the hood, a second 6 × 6 sheet in front of the first, G2 to its patch: gap 1e-13, 0.0001°, 0.0015 %, and Zebra
runs straight through the seam; the front patch keeps 1.5 mm RMS to the scan (0.9 mm on its own, with all six rows
free).

How it works: every point of the limit surface is a fixed linear mix of cage vertices. That mix is built once as a
sparse matrix with SubD to BREP's own Catmull-Clark rules (creases, open borders, Keep Corners), so the fitted
surface is exactly what SubD to BREP converts. Then, each round, the surface samples find their nearest scan points
and the scan's points their nearest surface points (pairs whose normals disagree, such as the far wall of a thin
part, or that lie too far are dropped), and one linear least-squares solve moves the cage: point-to-plane distances
both ways, the cage's tangential spacing held, a light fairness on its curvature variation (so round sections stay
round instead of shrinking). On a 124-vertex cage and a 92k-triangle scan a fit takes about 2 s.

Measured on a residual-limb scan (38 cm, 92k triangles), 10 rings × 12: the NURBS body is 1.2 mm RMS from the scan,
95 % within 2 mm; the lower half within 0.2–0.7 mm RMS. Larger misses are features a 12-around cage can't follow
(a muscle ridge, a round bump): Add Loops cuts loops there, or model the cage around them.

* Not yet: open trim lines (an edge of a patch held to part of a curve), symmetry, and cages with modifiers above
  the Subdivision (apply them first); for Drape Patch, splitting a patch where one span can't follow the scan, and
  neighbours with more than one face or trimmed edges.

## STEP Import and Export


### STEP import

**File → Import → NURBS (.step)**. Reads AP203, AP214 and AP242 files as exact trimmed NURBS.

* **Bodies:** MANIFOLD_SOLID_BREP, BREP_WITH_VOIDS and SHELL_BASED_SURFACE_MODEL. Each body becomes one NURBS object named after its product, in a new collection named after the file.
* **Surfaces:**
  * B-spline surfaces are kept as they are (rational, and unclamped or periodic knots are converted exactly).
  * Planes, cylinders, cones, spheres, tori, surfaces of revolution and linear extrusions become exact rational NURBS, sized to their face.
  * Offset surfaces use the kernel's offset. Rectangular trimmed surfaces use their basis.
* **Edges:** lines, circles, ellipses, B-splines and polylines, plus the 3D curve of surface, seam and trimmed curves. Each is cut exactly between its vertices, so both faces of an edge get the same curve.
* **Faces** are trimmed by their edge loops. When the kernel can't trim a face whose loop is its surface's own boundary (thin slivers), the whole surface is used. When the edges sit slightly off their surface (approximate offsets from other CAD systems), they are projected onto it.
* **Stitching:** each body's faces are stitched; solids come back closed. The tolerance is the file's own (×10), and at least 0.001 mm.
* **Units and assemblies:**
  * The file's units (mm, inch, m…) are converted, with an optional extra **Scale**.
  * Faces are built in millimetres and scaled at the end, because the kernel's tolerances suit part-sized numbers.
  * Assembly placements (transforms between representations, and mapped items) become object transforms, and a part used several times is imported once per placement.
* **Not read:** colours and layers, PMI, mesh and faceted bodies, wireframe-only geometry.
* **Faces that can't be built** are skipped and listed in the import report.

### STEP export

**File → Export → NURBS (.step)**. Exports the selected NURBS objects (or all visible ones with **Selection Only** off).

ISO 10303-21, AP214. Exact geometry: every surface is a B-spline surface (rational with weights where needed, e.g. exact circles, spheres and tori), and every edge a B-spline curve cut exactly to its range. **Analytic Surfaces** (on by default): what truly is a plane, a cylinder, a cone, a sphere, a torus, a revolution, an extrusion, an offset, a circle, an ellipse or a line is written as STEP's own **PLANE**, **CYLINDRICAL_SURFACE**, **CONICAL_SURFACE**, **SPHERICAL_SURFACE**, **TOROIDAL_SURFACE**, **SURFACE_OF_REVOLUTION**, **SURFACE_OF_LINEAR_EXTRUSION**, **OFFSET_SURFACE**, **CIRCLE**, **ELLIPSE** (arcs too) and **LINE**, as CAD programs write them, so the receiving app sees a real cylinder (a hole it can measure and edit, a boss, a tapered hole or countersink, a ball end or a round groove, a cylinder solid made of a Cylinder and two Planes) instead of a spline that looks like one. Each surface and edge is measured on samples and must fit within 1e-7 of the body's size; it is not read from history, so a drilled box or an extruded exact circle qualifies too. Cones are found from their straight rulings, frustums and pointed ones alike; tori from their circular parallels round one axis (ring tori only: a spindle torus, its tube wider than its ring, stays a B-spline). Ellipses are fitted as conics in their plane, the major axis first (an exact ellipse, or an exact circle or cylinder scaled unevenly, gives them). Any other face whose parallels are all circles round one axis (a revolved curve, a vase, a spheroid, a spindle torus, a hyperboloid) is written as a SURFACE_OF_REVOLUTION, its meridian the surface's own boundary curve as an exact B-spline. Any other face that is one profile moved along straight, parallel rulings (an extruded curve, an elliptic cylinder, a slanted extrusion, a smooth cylinder) is written as a SURFACE_OF_LINEAR_EXTRUSION: its profile a true CIRCLE or ELLIPSE when it is one, else the surface's own boundary curve as an exact B-spline. **Offset** of one surface gives the kernel's exact offset surface, which has no control points: it is written as what it truly is when analytic (an offset plane is a PLANE), else as an OFFSET_SURFACE of its basis (found through the Offset's history, offsets of offsets too; analytic or the basis' B-spline), always, with Analytic Surfaces on or off; its edges, which the kernel keeps only as fits ~1e-4 off it, are refitted onto the exact offset. An offset of a surface with a pole (a smooth sphere) has no normal there and no STEP form: the export says so and skips it. Thicken and Shell give B-spline fits and are written as such. A whole sphere is written as CAD programs write it, bounded by one VERTEX_LOOP at a pole and no seam (and read back that way too). Smooth (degree 3) circles, ellipses, cylinders, cones, spheres and tori are close approximations, not true ones, and stay B-splines (a smooth cylinder's side is still an extrusion of its B-spline rim, a smooth sphere's parallels are not circles). Turn it off to write everything as B-splines, as before. Full B-rep topology: shared vertices and edge curves, oriented edges, outer and inner bounds, face sense from the face's outward normal. Closed bodies become MANIFOLD_SOLID_BREPs, open ones SHELL_BASED_SURFACE_MODELs, one body per object, in world space. Unit mm / cm / m (Blender units are metres) and a scale. Checked by reading the files back in OpenCascade (FreeCAD): valid shapes, closed solids, the edge-filleted box with the same area and volume to 5 digits, imported radii exact. With Analytic Surfaces, an exact cylinder, a box with a drilled hole and a box with a cylinder boss read in FreeCAD as valid solids made of Cylinder and Plane faces with Circle and Line edges, their volumes right to 8 digits; so do a frustum, a pointed cone, a box with a tapered hole and one with a cone boss, as Cone and Plane faces, and a whole sphere and a whole torus (to 8 digits), a box with a spherical dimple and one with a toroidal groove, as Sphere, Toroid and Plane faces. An elliptic cylinder reads as Plane caps and a SurfaceOfExtrusion with Ellipse edges, the caps' area, the rims' length and the volume exact; extrusions of B-spline profiles (a wavy prism, a box with a wavy hole) read as SurfaceOfExtrusion faces lying on the B-spline originals to 1e-12 mm; a revolved vase (whole and a third of a turn), a spheroid and a hyperboloid read as SurfaceOfRevolution faces on their originals to 1e-12 mm (2e-5 mm at a rotated vase's poles); an offset loft, an offset of an offset and an offset revolved tube read as OffsetSurface faces (over a BSplineSurface or a SurfaceOfRevolution), the kernel's points and the edges on them to 1e-5 mm.
